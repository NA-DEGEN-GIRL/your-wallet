- 결정(명세 범위 안):
  - 잔액은 `getAccountInfo`(base64) + 원시 레이아웃 파싱으로 정했다(`getTokenAccountsByOwner`·`jsonParsed` 아님). 모르는 토큰은 조회조차 하지 않고, RPC의 decimals·`uiAmount`를 쓸 일이 없다.
  - SPL 받는 주소가 곡선 밖이면 차단한다(SOL은 L02 경고 유지). 상대의 토큰 계정 주소를 붙여넣는 흔한 실수로 토큰이 영구히 묶이는 것을 막는다. 파서도 같은 규칙(`RecipientOffCurve`)이라 저널·서명 경로에서 우회할 수 없다.
  - ATA 파생 실패(확률상 없음)는 빈 메시지 → 모든 검사에서 거부(패닉·`unreachable` 없음). transcript는 그 경우 0 바이트를 묶는다.
  - 승인 창(A01)의 텍스트 필드 안에서 한 줄 전체가 묶음 SOL 주소이면 주소 글꼴(가운데 굵게)로 그린다(`0x0502`의 mint·ATA). 그런 줄이 없는 필드는 예전과 같다.
  - S10 선택 계정 카드에 "허용 목록 토큰: …" 한 줄을 더했다(토큰 카드가 화면 아래에 있어 첫 화면에서 토큰 잔액이 보이지 않았다).

## 알려진 차이·남은 일

- USDT는 devnet 공식 mint가 없어 devnet에서 시험할 수 없다(07 미결 4). mainnet USDT는 mint·decimals·잔액 조회·미리보기 경로까지만 라이브로 확인했고, 실제 전송은 M9 mainnet 소액 체크리스트에서 본다. **mainnet SPL 전송은 M7-9 devnet E2E를 마치기 전까지 하지 않는다.**
- M7-5 오라클 교차 확인(`tools/sol-oracle/`, spl-associated-token-account·spl-token 크레이트)은 오프라인이라 하지 않았다. T_SPL 골든은 spec/07 §17.3 값(독립 구현)과 이 구현이 바이트까지 같다는 데까지 확인했다.
- `sendTransaction` `maxRetries:0`·SPL 실제 착지는 아래 수동 체크리스트(devnet)에서 본다.
- 한도 60,000 CU를 넘는 받는 주소(받는 ATA bump < 225, 약 2^-30)는 시뮬레이션이 CU 초과 실패로 보여 고위험 L05가 된다(차단 아님, D27).

## 수동 체크리스트 — devnet USDC (M7-9, spec/07 §17.6-8)

### 준비

1. 빌드: 저장소 루트에서
   ```powershell
   cargo build -p yw-app --release --locked
   ```
2. 시험 지갑: M7 체크리스트와 같은 시험 지갑(`abandon` × 11 + `about`)을 쓴다. 실제 자산이 든 니모닉은 쓰지 않는다. 공개 니모닉이라 다른 사람이 devnet 잔액을 옮길 수 있으므로 금액은 작게 한다.
3. S10 `Solana` 탭 → 클러스터 `Solana devnet (테스트)` → `RPC (solana:devnet): 연결됨 (genesis 확인)`(엔드포인트는 M7 체크리스트 준비 4와 같이 넣고, URL은 어디에도 남기지 않는다). 계정 A = `Solana 4`(m/44'/501'/3'/0'), B = `Solana 5`(m/44'/501'/4'/0'), C = `Solana 6`(m/44'/501'/5'/0'). 없으면 `계정 추가`로 만든다.
4. SOL: A의 `받기` → `주소 복사` → `https://faucet.solana.com`(devnet)에서 1 SOL.
5. USDC: `https://faucet.circle.com` → 네트워크 **Solana Devnet**, 토큰 **USDC** → A의 **지갑 주소**를 붙여넣어 요청(faucet이 A의 USDC 토큰 계정을 만든다).
6. 탐색기: `https://explorer.solana.com/?cluster=devnet`(읽기만). 로그는 M7 체크리스트 준비 5와 같다(`sol.*` 줄에 URL·호스트·주소·mint 없음).

### 항목

- [ ] **M7-S1 토큰 잔액 표시** — A 선택 → `새로고침`. 선택 계정 카드에 "허용 목록 토큰: {받은 양} USDC", 아래 카드 "토큰 (선택한 계정)"에 USDC 잔액·원시 단위·mint `4zMM C9sr t5Ri …`. 탐색기에서 A의 Tokens 탭 USDC 잔액과 같다. B를 선택하면 "0.000000 USDC — 이 계정에는 아직 USDC 토큰 계정(ATA)이 없습니다".
- [ ] **M7-S2 새 수신자(ATA 생성)** — A의 토큰 카드 `USDC 보내기`(또는 `보내기` → `자산` USDC) → 받는 주소 B, 금액 `1` → `검토` → 승인 창: 제목 `[Solana devnet (테스트)] 토큰 전송: 1.000000 USDC`, 요약 "…1.000000 USDC를 아래 주소로 보냅니다"와 B 주소 전체, `자산·금액 · USDC`에 `1,000,000 (원시 단위, decimals 6)`·mint·`SPL Token (Tokenkeg…)`·보내는 토큰 계정·받는 토큰 계정 전체(주소 글꼴), `ATA 생성` "받는 토큰 계정이 없습니다(RPC 참고) — 이 거래가 만듭니다. 생성 비용(rent) 최대 0.001488440 SOL(1,488,440 lamports)…"(그날 rent 값), `최대 총 차감` "SOL 최대 … (수수료 최대 5,000 + 토큰 계정 생성 rent 1,488,440)", 시뮬레이션 "성공(CU 약 14,000–30,000)". `승인` → 결과 화면 "서명하고 저널에 기록한 뒤 전송했습니다" → 1분 안에 `성공`. 탐색기: 같은 서명 Success, B의 USDC 토큰 계정(승인 창의 "받는 토큰 계정"과 같은 주소)이 생기고 1 USDC, A의 SOL 감소 ≤ 승인 창의 SOL 최대. `새로고침` 뒤 A USDC −1, B USDC 1. 활동에 "토큰 전송: 1.000000 USDC" 1줄.
- [ ] **M7-S3 기존 ATA** — 다시 A → B, 금액 `0.5` → 승인 창 `ATA 생성` "받는 토큰 계정이 이미 있습니다(RPC 참고) — 생성 비용 없음", `최대 총 차감`의 rent 0 → `승인` → `성공`. A의 SOL 감소 = 수수료만(5,000 lamports + 우선 수수료). B USDC 1.5.
- [ ] **M7-S4 토큰 보내기 최대** — 먼저 A → B로 SOL `0.01` 보내기(B의 수수료용). B 선택 → `보내기` → `자산` USDC, 받는 주소 A, `보내기 최대` 체크 → `검토` → 승인 창 금액 1.500000 USDC, 정보 "보내기 최대: 보낸 뒤 이 계정의 USDC 잔액은 0이 됩니다(SOL은 남습니다)", A의 토큰 계정이 있으므로 rent 0 → `승인` → `성공`. B: USDC 0.000000(토큰 계정은 남음), SOL = 0.01 − 수수료.
- [ ] **M7-S5 SOL 부족 차단** — A → C로 USDC `1`(C의 ATA 생성, C에는 SOL 없음). C 선택 → `USDC 보내기` → 받는 주소 A, 금액 `1` → `검토` → 승인 창 맨 위 차단 "보낼 수 없습니다: SOL이 부족합니다: 수수료와 받는 토큰 계정 생성비(필요할 때)를 내고도 0.000650240 SOL이 남아야 합니다(…)" → `승인` 비활성 → `거부`. 서명·전송 없음.
- [ ] **M7-S6 허용 목록 밖 토큰 숨김** — Circle faucet에서 **EURC**(Solana Devnet)를 A의 지갑 주소로 받는다(없으면 다른 devnet SPL 토큰). 탐색기 A의 Tokens 탭에 EURC가 보인다. 앱에서는 `새로고침` 뒤에도 토큰 카드·선택 카드·보내기 `자산` 라디오·스캔 어디에도 EURC가 없다(USDC만). 로그에도 EURC mint가 없다.
- [ ] **M7-S7 받는 주소 차단** — A → `보내기` → `자산` USDC → 받는 주소에 A의 USDC 토큰 계정 주소(M7-S2 승인 창의 "보내는 토큰 계정" 또는 탐색기) 입력 → 빨간 띠 "토큰은 일반 지갑 주소로만 보낼 수 있습니다…" (E-SOL-006), `검토` 비활성. 같은 주소로 `자산`을 SOL로 바꾸면 차단 대신 고위험 안내(L02)로 바뀐다(보내지 않는다). 받는 주소에 devnet USDC mint `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU` → "받는 주소가 프로그램·시스템·토큰 mint 주소입니다…"(E-SOL-001).

### 정리

- 남은 devnet 잔액은 그대로 두어도 된다(시험 니모닉). 클러스터는 `Solana mainnet`으로 돌려 두어도 된다.
- mainnet USDC·USDT 실제 전송은 M9 소액 체크리스트에서만 한다.
