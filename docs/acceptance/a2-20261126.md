- 이 빌드는 시험용이다: 탭재킹·접근성 방어와 생체 인식(A5)이 없다. 공개 시험 니모닉과 합성 비밀번호만 쓴다. 실제 복구 단어와 실제 자금을 넣지 않는다.

## 시험 기기 실행을 끝내지 못한 까닭

1. 첫 실행(2026-11-25): 내내 adb가 `unauthorized`였다. 기기 화면의 "USB 디버깅 허용"은 에이전트가 누르지 않는다. 13행 가운데 하나도 돌지 않았다.
2. 둘째 실행(2026-11-25): 기기가 `device`로 보여 행 1을 마치고 2·3·11·12의 일부와 10의 깃발을 본 뒤, 약 0.5 MB의 스크린숏을 한 번에 받는 `adb pull`에서 USB 연결이 끊겼고, 다시 나타났을 때는 `unauthorized`였다(앞의 허용은 그 연결에만 유효했던 것으로 보인다). 기기에는 마지막 코드의 release 시험 빌드가 남아 있다(지갑 없음, W01에서 멈춤; spec/09 §2.6은 A2 끝의 마지막 빌드를 남기는 것을 허용한다). A2-8이 남긴 시험 패키지는 이 실행이 먼저 지웠다.
3. 2026-11-26: 주인 결정으로 시험 기기를 다시 쓰지 않는다. 이 기록을 만드는 동안 기기에 닿지 않았고, 에뮬레이터도 다시 돌리지 않았다(코드가 바뀌지 않았다).

## 에뮬레이터가 덮지 못하는 것

- arm64 `libyw.so`의 전체 흐름(같은 소스의 arm64 빌드는 게이트가 만들고 검사하며, 시험 기기에서는 위 칸만큼만 돌았다).
- 하드웨어 TEE Keystore의 기기 키(에뮬레이터는 보호 하드웨어가 아니다): 시험 기기의 A2-4b·A2-8이 감싸고 풀기를 봤다. 화면 잠금이 있을 때의 경우는 여전히 주인 체크리스트(AND-K1–K3)다.
- API 29의 동작(최근 앱 축소판은 API 33 미만에서 `FLAG_SECURE`에만 기댄다)과 작은 화면의 배치: 행 2의 다른 결과가 그 예다.
- 제조사 전력 관리 아래의 백그라운드 잠금, 실제 손가락 터치(모두 `adb` 주입 입력이다).

## 찾은 것

에뮬레이터 실행에서 찾아 `62f766a2`에서 고친 것(고친 빌드로 다시 돌려 확인함): (고침 1) W08의 2초 누르기가 끝나지 않음, (고침 2) 언어를 바꿔도 주 화면의 띠가 그대로, (고침 3) `-DeviceTest` 장애 지점을 읽지 못함.

고치지 않고 A3로 넘긴 것:

1. **비밀 창의 띠가 내용과 함께 스크롤된다**(시험 기기 A2-7 검토·A2-8의 화면 dump를 이 기록을 쓰며 다시 읽어 찾음, 2026-11-26). 주 화면은 띠를 스크롤 밖 맨 위에 두지만 `SecretActivity`는 스크롤되는 본문 안에 그린다. 화면이 작으면 활성 칸으로 스크롤될 때 시험용·약한 보호 띠가 화면 밖으로 나간다(디버깅 띠는 남았다; 위로 밀면 다시 보이고 닫을 수는 없다). spec/15 §1.1의 "모든 화면 위"에 맞게 스크롤 밖에 고정하는 것은 A3의 첫 코드 커밋이다(spec/15 §9.1, §17 A3).
2. **Windows를 말하는 엔진 문구가 Android에도 보인다**: S01 "이 PC에서만", S07 "Windows를 잠그거나 절전에 들어가면", 가져오기 `완료`의 QuickNode 안내 "이 Windows 사용자만", 주 화면 상태 줄의 `브라우저: 사용 불가 E-PIPE-001`(Android에는 파이프가 없다). 문구만의 문제이고 잠금 동작은 명세대로다(spec/15 §18 49).
3. release 첫 시작에 ART의 `JNI critical lock held for ~16 ms` 경고 한 줄(플랫폼의 시간 경고, CheckJNI 오류 아님). 고칠 것 없음.
