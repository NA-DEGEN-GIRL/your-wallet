# 확인 1개 = 확정 (D32) — 2026-10-29

- 결정: spec.md D32(사용자 결정). 설정한 RPC를 신뢰한다. 모든 체인에서 확인 1개가 최종이고, 추가 확인 수·`finalized` 대기·긴 안전 타이머(Solana 90초 하한)는 두지 않는다. 확인 1개로 확정한 거래가 재구성으로 빠지는 것은 체인 문제로 보고 범위 밖이다(spec.md §2.2).
- 범위: spec/03 §4.5·§5.2(EVM), spec/08 §12.1–§12.4(Bitcoin), spec/07 §13.1·§14.2–§14.3·§15.2·§16·§17.4(Solana), spec/04 §2.6 상태 문구·T-EVM-SENT·T-SOL-SEND-NOW.
- 저널 형식: 바뀌지 않는다(EVM 상태 3 `Included`, BTC 상태 7 `Confirmed`, SOL 레코드 그대로). 이전 빌드가 `Included`로 남긴 EVM 레코드는 다음 추적 라운드가 RPC 호출 없이 `Finalized`로 옮긴다. 확인 6 미만으로 추적 중이던 BTC `Confirmed` 레코드는 다음 라운드에서 끝난 항목으로 activity에 옮겨진다. SOL `Pending` 레코드는 새 규칙(한 번의 높이 라운드)으로 계속 추적된다.

## 체인별 동작

| 체인 | 이전 | 지금 |
|---|---|---|
| EVM | 영수증 → `Included`, 60 s마다 `finalized` 태그(거부 시 latest − 64) ≥ N과 블록 해시 재확인 → `Finalized`, 다르면 `Reorged` | 검증한 영수증(해시·보낸 주소·nonce·블록 필드)이 블록에 있으면 같은 라운드에서 `Included` + `Finalized`(한 번의 저널 쓰기). D20 즉시 해제. `Reorged` 전이·`finalized` 조회 삭제 |
| Bitcoin | 확인 6까지 추적(`확인 n/6`, `확정(6+)`), 교체 사슬도 교체본 확인 6까지 | `BTC_FINAL_CONFIRMATIONS` = 1: 확인 1이면 추적 끝·activity 이동. D20 해제·잔돈 사용·포기/공개 거래 충돌 해소도 확인 1(원래 1이던 것은 그대로). 표시 `확인 대기`/`확정` "(서버 기준)". 팁 높이 이상값 검사(Core 팁보다 높은 인덱서 높이 = 0 확인, 확정 높이보다 낮은 팁이면 끝나지 않음)는 유지 |
| Solana | 모든 조회 `finalized`, `confirmed`는 처리 중. 만료 = 높이 > lvbh + 이력 null + 벽시계·단조 시계 90 s, 연속 2라운드 | 모든 조회 `confirmed`, `confirmed`/`finalized` 상태 = 종결. 만료 = `confirmed` 높이 > lvbh + 이력 null(응답 슬롯 ≥ 높이 슬롯) **한 라운드**, 시계 조건 없음 → 바로 새 승인·재서명 가능. 그 전에는 `지금 다시 전송`이 같은 서명 거래를 즉시 다시 보냄. 저널은 첫 전송 전 기록(변경 없음) |
