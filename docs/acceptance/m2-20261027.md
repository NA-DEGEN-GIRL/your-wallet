## 차이·명세 수정

명세 수정(최소, 이 커밋):
- spec/03 §11.1: 빌더 3종에 서명 계정 인수 `account: Address`가 없어 추가했다(`ApprovalDraft.account`를 만들 수 없음). 표시 문자열 재검사가 실패할 수 있으므로 반환형을 `Result<ApprovalDraft, DisplayError>`로 했다(입력은 모두 이스케이프하므로 방어 중복).
- spec/03 §6.4 `SimulationDiff`: `events`(user와 무관한 분류 로그 전체 — R4·R6 판정 입력), `omitted_rows`(E08), `native_emitter_mismatch`(yw-core는 로그를 쓰지 않으므로 yw-app이 이 값으로 `native-emitter-mismatch`를 기록)를 더하고, `AssetChange.delta`를 `Option<Delta>`(None = `합산 불가`, E09)로 했다. 행 순서는 보냄(합산 불가 포함) → 받음 → 승인.
- spec/03 §9.3 `SiweMessage`: fuzz 불변식(필드 재조립 == 원문)과 S02(userinfo)를 위해 원문 토큰 필드(`scheme_explicit`, `domain`, `has_userinfo`, `address_text`, `chain_id_text`, `issued_at_text`, `expiration_time_text`, `not_before_text`, `resources_present`, `trailing_lf`)를 명시했다.
- spec/03 §2.3: `U256`의 `to_be_bytes`·`to_u64`·`to_quantity`·`to_decimal_string`은 `self`를 값으로 받는다(Copy 타입, clippy pedantic `wrong_self_convention`).
- spec/03 §11.5: `consume`은 `risk == Blocked` 요청에 `ApprovalError::Blocked`(방어 중복), `replace`는 kind·origin·chain·account·signer가 같아야 한다고 명시했다.
- spec/03 §1.2: "구현 시 확인" 레지스트리 행은 오프라인이라 탐색기·`eth_getCode`로 확인하지 못했다. 표 그대로 두고(EIP-55 문자열 유효성·코드 상수 일치는 `registry_rows_spec_03_1_2`로 확인) 확인 시점을 M4 `live_probe`(M4-13 전)로 옮겼다.
- spec/09 §3.8: 프로브 형태 픽스처 S1h(`maxUsedGas` 없음, HyperEVM)·S3c(revert `0xdeadbeef`)·S4h(-32003)·S16(자기 자신 전송, 로그 없음·12,000 gas) 행을 추가하고, S9 변형을 파일 S9a–S9i로 명시했다.
- spec/09 §3.13: V14 골든의 고정 입력(`ChainFacts::default()`, `now_unix_ms` = created, signer `Derived(0)`, App 출처라 E28 포함)을 적었다.
- spec/09 §5.3 M2-1: "체크 + 2.0 s → `Approved`"를 코어 판정(`High`·`ack_required`·차단 없음·`issue`→`consume`)으로 바꾸고 입력 순서는 04 AP-2(M3)·AP-6(M4-12)으로 돌렸다(상호작용 상태 기계는 yw-app `ui::interaction`).

구현 선택(명세 범위 안):
- `ChainFacts.account_code`는 명세대로 `CodeKind`(기본 `Eoa`).
- `typed data` 스키마 인식의 레지스트리는 `chain_id`로 찾은 내장 체인 표를 쓴다(사용자 체인은 레지스트리가 없어 Permit2·Seaport 미인식, §1.2와 같음).
- P03(일반 UTF-8 메시지, 정보)은 숨은 문자가 있으면(P02) 붙이지 않는다. 이스케이프한 텍스트가 270,000바이트를 넘으면 hex로 보이고 P02를 붙인다(P01은 비UTF-8에만).
- `personal_sign`의 App 출처(실제로는 없음)에서 SIWE는 S01(fail closed).
- 상태 0x0인데 `error`가 없으면 `returnData`를 §7.4로 해석한다.
- revert(`status 0x0`)는 E02만 내고 E03·E07 등은 더하지 않는다(verdict 우선순위 `Reverted`).
- 요청 준비 단계의 `EvmSpeedUp`/`EvmCancel` 표시 키 `0x0125`(대체 대상)는 빌더 인수에 대체 대상 정보가 없어 M4(§4.6)에서 더한다.
- `evm::simulate::needs_resimulation`/`SIM_FRESHNESS_MS`(§6.6 1–3 판정), `simulate_request`(§6.1 요청 바이트), `codec::{sha256, keccak256}`(골든 독립 검사·yw-app용 해시 도우미)를 더했다.
- yw-app `rpc::evm`: `parse_simulate_response(body, expected_id)`(4 MiB·로그 1,024·topics 4·data 65,536 → `TooLarge`, 문법·필수 필드·`id`·`jsonrpc` 위반 → `Malformed`, 코드 429 → `RateLimited`)와 `simulate_http_outcome(status, …)`(HTTP 429 → `RateLimited`, 그 밖 비200 → 전송 오류).
- `sign_transaction`은 서명 전에 승인 chain id와 거래 chain id 일치, §3.1 불변식(`Eip1559Tx::validate`)을 확인한다(위반 → `KindMismatch`, 서명 없음).
