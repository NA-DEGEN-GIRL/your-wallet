# YubiKey 계정 판정 기록 — 2026-11-04 (코어·백엔드), 실제 YubiKey 수동 항목은 사용자 수행

- 범위: spec.md D33, [spec/10](../../spec/10-yubikey.md) 전체, spec/02 §4.6(tag 5 `HwKey`, `MAX_RECORDS` 54, `PAYLOAD_CT_MAX` 16,384), spec/01 §3의 yw-win feature 목록(`Win32_Security_Credentials` 추가).
- 사용자 요청: 니모닉에서 고른 키를 한 번 파생해 하나 이상의 YubiKey 5(최신 펌웨어)에 가져오고, 그 뒤 PC에는 비밀 없이 공개키·일련번호·슬롯 표만 두고 YubiKey에서 PIN + 터치로 서명한다. 슬롯마다 파생 인덱스를 고르고(YubiKey N개 = secp256k1 키 N×2개), 다른 YubiKey와 같은 경로는 명시적 "백업 복사본"일 때만 허용한다.
- 의존성: **추가 없음**(`Cargo.lock` 변경 없음). windows-sys feature `Win32_Security_Credentials`만 더했다(SCard*). AES·3DES는 Windows CNG(`BCRYPT_AES_ECB_ALG_HANDLE`·`BCRYPT_3DES_ECB_ALG_HANDLE`)로, yw-core에는 블록 암호 구현이 없다.
- **하드웨어 안전 규칙:** 이 작업 중 실제 YubiKey·스마트카드에 어떤 APDU도 보내지 않았다. 자동 시험은 모두 프로세스 안 APDU 에뮬레이터(`yw_core::yubikey::mock::MockCard`)로 돈다. 실제 리더를 쓰는 코드는 읽기 전용 수동 진단 `yw_win::pcsc::tests::pcsc_readonly_probe`(`#[ignore]`, 게이트의 `fuzz_lite` 필터에 걸리지 않음)뿐이다.
- 구현 상태와 남은 UI 작업: spec/10 §13.

| ID | 절차 | 기대 결과 | 판정 |
|---|---|---|---|
| Y-01 | `cargo test -p yw-win --offline --locked pcsc_readonly_probe -- --ignored --nocapture` | 리더 이름이 보이고, 각 명령에 `SW [90, 00]`(KDF `F9`·메타데이터는 미지원이면 `6A 88`/`6D 00`도 정상). 이 진단은 SELECT·GET VERSION·GET SERIAL·GET METADATA(9B, 80)·GET VERSION(F1)·GET DATA(6E, F9)만 보낸다 | 대기 |
