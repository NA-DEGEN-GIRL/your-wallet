### 차등 오라클 (M8-3, 08 §14.3) — 미수행

`tools/btc-oracle/`(rust-bitcoin `=0.32.x`)는 로컬 레지스트리에 `bitcoin` 크레이트가 없어 오프라인으로 만들 수 없었다(`bitcoin_hashes`·`bech32`만 있음). 대신 BIP84 주소(about testnet4 받기 0–19·잔돈 0–19, 받기 155)는 독립 Python 구현(순수 secp256k1·BIP32·bech32, 저장소 밖)으로 다시 계산해 앱 결과와 같음을 확인했다. 온라인 환경에서 수행할 일로 남긴다(아래 체크리스트 M8-L).

### release 스모크 (개발자 확인, 판정 아님)

`target\release\yw-app.exe`를 버리는 `LOCALAPPDATA`(스크래치 폴더, 끝나고 삭제)로 실행하고 창 메시지(`WM_COMMAND`·`WM_SETTEXT`·`WM_CHAR`)와 `PrintWindow` 캡처로 조작했다. 실제 `%LOCALAPPDATA%\YourWallet`은 만들지도 건드리지도 않았다(실행 뒤에도 없음). 전송·서명 0회. 스모크는 아래 10번 수정 뒤, 코드 검토 수정(자동 항목 마지막 행) 전의 release 빌드로 했다(검토 수정은 화면 흐름 중 [포기]·사전 검사·추적 판정만 바꾼다).

1. 첫 실행 → `기존 지갑 가져오기` → S05에 고정 문구 "이 지갑은 BIP84(bc1q…) 주소만 찾습니다" → 비밀번호 → 시험 니모닉(`abandon` × 11 + `about`) → 첫 주소 `0x9858EfFD232B4033E47d90003D41EC34EcaEda94` → `맞습니다` → `나중에`.
2. 설정 → 네트워크 → `bitcoin:testnet4` `교체`에 개발 설정의 URL 저장(값은 기록하지 않음, 목록에는 `https://●●●●.quiknode.pro/●●●●`) → `테스트` "엔드포인트가 작동합니다. (Bitcoin testnet4, chain testnet4)".

구현 결정(명세 범위 안):
- 계획은 보내기 폼의 `검토`에서 만든다. 계획 오류(dust, 잔액 부족, 추정 없음, 상한 해제 필요, B01)는 폼에 남고 승인 요청을 만들지 않는다(08 §10). 승인 창은 대기열 항목의 계획으로 초안만 만든다. B01(10,000 sat/vB 초과)은 폼에서 거부한다.
- testnet4처럼 추정이 없으면 폼이 `직접 입력`과 하한으로 바뀌고 바로 다시 `검토`할 수 있다.
- 사전 검사 거부는 `Rejected`, 잔돈 인덱스 재사용, 입력이 폼으로 돌아온다.
- 키 작업자가 meta `btc`의 유일한 작성자이고 모든 변경을 화면에 알리기 전에 저장한다(받기 주소는 `receive_next` 저장 뒤 표시). 순서는 언제나 meta 쓰기 → 저널 쓰기.
- 저널 `entry_id` = 승인 id. `SendPlan`·`VerifiedSignedTx` 필드는 읽기 전용이라 저널 레코드는 서명 후 검증을 통과한 거래로만 만든다.
- 잠금은 충돌처럼 다룬다: 잠금 해제 뒤 저널을 읽을 때마다 `Broadcasting` → `BroadcastUnknown`. 잠긴 동안 온 전송 결과는 버리고 추적이 다시 확인한다.
- `reject-reason`은 아는 토큰(또는 `unknown`)만 로그에 남기고 원문은 어디에도 남기지 않는다. E-BTC-008 본문도 기록하지 않는다(04 §7의 debug 원문 기록은 구현하지 않음).
- 1–2단계의 모든 불일치(IBD·헤더 차·mediantime·팁 역행 포함)는 그 세션을 E-RPC-006으로 막는다.
- `live_probe`는 `YW_BTC_ESPLORA_MAINNET`·`YW_BTC_ESPLORA_TESTNET4`로 다른 공개 Esplora를 고를 수 있다(설정과 같은 형식 검사).
