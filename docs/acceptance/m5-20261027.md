### headless yw-host ↔ yw-app E2E (개발자 확인)

`target\debug\yw-host.exe`를 Node에서 stdio로 구동하고, `target\debug\yw-app.exe --background`를 버리는 `LOCALAPPDATA`(스크래치 폴더, 끝나고 삭제)와 debug 전용 `YW_TEST_PIPE_NAME`(`\\.\pipe\YourWallet.test.e2e.<pid>`)으로 실행했다. 실제 `%LOCALAPPDATA%\YourWallet`은 만들지도 건드리지도 않았다. 앱은 vault가 없는 상태(NoVault)다. 결과 23/23 통과:

- 잘못된 origin 인자 → 종료 2, stdout 0바이트.
- yw-app 없음(`YW_TEST_NO_SPAWN=1`): 요청 2개 → 각각 4900 "Wallet is unavailable."(송신 sequence 1·2, requestSequence 1·2), 중간의 형식 오류 프레임 출력 없음, 1 s 뒤 종료 3.
- `YW_TEST_DATA_DIR`의 `{"version":1,"browserAutoLaunch":false}` → 34 ms에 4900, 종료 3, yw-app 실행 안 됨.
- 실제 yw-app: `eth_chainId` → `"0xaa36a7"`(송신 sequence 1); JSON 아닌 프레임 → 무응답; 모르는 키가 든 봉투 → 그 요청만 -32600; `eth_sign` → 4200; 잘못된 params → -32602; vault 없음 `eth_requestAccounts` → 4100; 엔드포인트 없음 `eth_blockNumber` → 4901; `wallet_switchEthereumChain 0x1` → null + `chainChanged "0x1"` 이벤트(sessionId·activationNonce 일치); `0x89` → 4902; `wallet_addEthereumChain` → 4200; `net_version` → `"1"`; cancel → 무응답; http origin(토글 꺼짐) → 4100; 지난 기한 → -32603 "Request timed out."; 오류 뒤 `web3_clientVersion` → `"YourWallet/0.3.0"`(스트림 유지).

## spec 수정·결정 (최소 변경)

- spec/05 §6.2-2: `kind: "cancel"` 프레임의 형식 오류는 상관 필드가 있어도 버린다(cancel에는 응답하지 않는다는 §6.1과 맞춤).
- spec/05 §10.1: yw-app도 debug 빌드에서만 `YW_TEST_PIPE_NAME`(`\\.\pipe\`로 시작)을 쓴다 — headless E2E가 실제 사용자 pipe 이름·데이터 폴더를 쓰지 않게.
- spec/05 §2.3: yw-host의 `include_str!`는 `lib.rs`에 둔다(테스트가 쓴다, 경로 같음).
- spec/01 §7.5: yw-win `pipe`에 `ServerError::Stopped`, `Server::stop_handle() -> ServerStop`(앱 종료 시 accept 중지), `Server::security_summary()`(R-P2 DACL 확인) 추가.
- spec/03 §3.2: dApp `nonce`는 §3.7 단계 4에서 판정하고, 다르면 준비 중 창을 닫고 -32602(실패 표시 없음).
- 구현 결정(명세 범위 안):
  - read 워커는 자체 체인 확인 캐시를 쓰고(`yw-rpc`와 별도, 결과는 UI에 알려 999 첫 고정·차단 표시에 반영), `Unverified`는 다음 read에서 다시 확인한다(spec/03 §1.4).
  - RPC URL 저장·삭제·템플릿 생성 시 그 체인의 확인 상태를 `yw-rpc`·read 워커·차단 목록에서 초기화한다(spec/03 §1.4 "URL이 바뀌면 상태 초기화"; M4는 사용자 체인만 했다).
  - 잠금 해제 병합: 캐시가 있으면 grant 체인을 캐시로 저장(dApp은 이미 그 체인), 캐시가 없으면 grant 체인으로 캐시를 채우고 `evmChainId`와 다르면 `chainChanged`.
  - 연결 창 계정 순서 = 지갑 계정 목록 순서, 기본 선택 = 기존 grant 계정, 없으면 계정 0.
  - typed data 사실 조회(주소 분류·토큰 메타)는 최선 노력: 엔드포인트 없음·체인 미확인이면 조회 없이 표시(차단 없음).
  - 브로드캐스트 결과 → dApp: `Sent`·`Rejected{known}`·`Unconfirmed` → tx hash, `HashMismatch`·`Rejected{!known}`·`ChainMismatch` → -32603 "Transaction broadcast failed."; 서명·저널 실패 → -32603 "Internal error.".
  - vault 없음에서 `wallet_revokePermissions` → 4100(계정 관련 메서드 규칙).
  - 확장 쪽(에이전트 구현): page `freeze` 리스너는 `document`에(이벤트가 window로 오지 않음), 크기 초과 응답은 page에 -32603 "Response too large.", provider는 요청을 `JSON.parse(JSON.stringify(...))` 형태로 보냄(`undefined` 필드 제거), 10 s 브리지 대기는 요청마다, 5 s 연결 시간 초과는 port를 실제로 연 시점부터, `onSuspend`로 닫힌 native 연결은 backoff 실패로 세지 않음.
  - yw-host: stdin 읽기·할당 실패 → 6, 절단·크기 초과만 4; SID 조회 실패 → UNAVAILABLE; hello-ack `protocol`과 settings `version`은 엄격 정수(`1.0` 거부).
