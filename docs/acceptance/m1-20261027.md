## 차이·명세 수정

- spec/09 §5.2 M1-3: V-FS를 M3-12로 옮겼다(위 표).
- spec/09 §3.1: `bip32.json` 구조를 실제 파일(`{"valid": …, "invalid": [[키, 사유]]}`, 경로의 `<sub>H</sub>` → `'`)로 고쳤다.
- spec/02 §7.2: `unlock`이 `PayloadCorrupt`면 상태를 `Corrupt { prev_available }`로 바꾼다(§6.3 "`.prev` 복구를 제안"과 S09 화면 흐름에 맞춤). 행 1개 추가.
- spec/02 §6.3: "구조 손상"에 `UnsupportedVersion`·`UnsupportedParams`도 포함됨을 명시(→ `Corrupt`).
- spec/02 §6.2: V-3("공개 API로 열면 `UnsupportedParams`")을 판정할 공개 함수 `check_vault_header(bytes) -> Result<u64, VaultError>`(§4.5 1–7, KDF 없음)를 추가했다. `peek_generation`은 이 결과의 `ok()`다.
- spec/02 §2.1: 단어 목록 SHA-256 확인 완료로 고쳤고, `OnceLock` 값은 스택 32 KiB 배열 lint(`large_stack_arrays`) 때문에 `Box` 배열이다.
- spec/02 §11.1: `ScriptedRandom`의 스크립트 뒤 바이트는 상수가 아니라 결정적 바이트열이다(상수열이면 DEK 고착 검사에 걸린다).
- spec/01 §2.2: `fill_random`의 오류 타입을 spec/02 §1.1과 같은 `KeyError::RandomnessUnavailable`로 고쳤다.
- 구현 선택(명세 범위 안): `change_password`는 `BackupPending`·`Unlocked`에서 허용, 두 번째 커밋(`PayloadRewrite`) 실패 시 오류를 돌려주며 vault는 이미 새 비밀번호다. raw key 가져오기는 중복 검사 → 15개 상한 순서.
- M0 잔여 작업: `scripts/lib/strict-json.mjs`가 `"__proto__"` 키를 거부한다(프로토타입 교체 방지). `scripts/probe-rpc.mjs`는 `rpc.json`을 `decodeUtf8`·`parseStrictJson`으로 읽고(64 KiB 상한, 객체만), 저장소 안 판정을 `realpath` + `path.relative`로 한다. 이전 판정은 `import.meta.url`의 `pathname`을 써서 저장소 경로의 `#`가 `%23`으로 남아 항상 "저장소 밖"으로 판정되었다. 출력 문구·종료 코드는 그대로다(오프라인 확인: 저장소 안 파일 → 거부, 없는 파일·`__proto__`·중복 키 → "읽을 수 없습니다", 빈 객체 → 전 항목 `skip`, 종료 0).
