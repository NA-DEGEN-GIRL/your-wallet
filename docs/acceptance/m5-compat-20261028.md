## 설계 결정 (spec/05 §2.12 요약)

| 주제 | 결정 | 이유·대가 |
|---|---|---|
| 모드 전달 | 팝업이 `chrome.storage.local.compatMode`에 저장 → ISOLATED content가 document_start에 한 번 읽음(3 s 상한, 실패는 `off`) → `bridge-init.compatMode`로 MAIN world provider에 전달. 문서마다 고정, 다음 페이지 로드부터 적용 | 새 권한 없음. MAIN world 동기 전달은 `scripting` + 호스트 권한(동적 content script)이 필요해 쓰지 않았다. 대가: 저장소 응답 전 수 ms의 임시 구간 |
| 첫 EIP-6963 알림 | 모드가 정해질 때 1회(그 전 `requestProvider`는 그때 답함, `bridge-init`이 10 s 없으면 기본 신원) | 한 페이지에 신원 하나만 알리기 위해(같은 uuid 두 신원 또는 "Your Wallet"+"MetaMask" 중복 방지). 기본 모드도 알림이 수 ms 늦어진다(EIP-6963 dApp은 계속 듣는다) |
| `window.ethereum` 우선권 | 호환 모드 확정 시 `{ get: () => provider, set: 무시, configurable: true, enumerable: true }` 접근자. 검문점(확정, `requestProvider`, `DOMContentLoaded`, `load`)마다 남이 재정의했으면 되찾음. non-configurable 선점자는 대입(그 지갑의 setter)만 시도 | `configurable: false`는 뒤에 `defineProperty`를 부르는 다른 지갑 스크립트를 TypeError로 죽인다. setter 무시는 MetaMask식 `window.ethereum = x`를 예외 없이 무력화. 대가: 검문점 사이의 재정의는 잠시 이긴다, non-configurable·쓰기 불가 선점은 못 이긴다 |
| 기본 모드 | 종전 규칙 그대로(없을 때만 일반 데이터 속성, 가로채기·되찾기 없음) | D22 "기본 꺼짐", 다른 확장과 공존 |
| EIP-6963 신원 | 호환 모드는 호환 신원만 알림("Your Wallet" 알림 없음): `MetaMask`/`io.metamask`, `Rabby Wallet`/`io.rabby`. 아이콘은 우리 PNG, uuid 페이지당 하나 | 중복 목록 방지, 남의 로고 복사 금지 |
| 가로채기 | document_start에 window capture 리스너. 호환 모드 확정 뒤 우리 detail이 아니고 rdns(소문자)가 `io.metamask`·`io.metamask.flask`·`io.rabby`면 `stopImmediatePropagation()`. 다른 rdns·검사 불가 detail은 통과. 기본 모드·확정 전 없음 | window 대상 이벤트는 capture 리스너가 먼저 실행되고 페이지 스크립트는 우리보다 늦게 등록한다 |
| 플래그 | getter: `isMetaMask`(호환 모드), `isRabby`(rabby), `_metamask`(호환 모드에서 `{ isUnlocked }`, `requestBatch` 없음). `isYourWallet` 항상 true | 같은 provider 객체를 이미 잡은 코드도 확정 뒤 올바른 값을 본다 |
| `_metamask.isUnlocked()` | `eth_accounts`가 비어 있지 않으면 true(연결 + 잠금 해제), 아니면·오류면 false, 거부 없음 | 우리 권한 상태 기준 |
| yw-app 표시 | content→bg `request.compatMode`(호환 모드일 때만) → native `context.compatMode`(선택 키, v1 유지). yw-app은 `"metamask"`·`"rabby"`만 수락(그 밖은 그 요청만 -32600), `SiteRequest.compat_mode` → 연결 창·서명 승인 창 배지 "호환 모드: MetaMask"/"호환 모드: Rabby". origin은 `port.sender` 그대로 | 페이지는 모드를 위조해도 자기 provider 표시만 바뀐다. yw-app 배지는 content가 저장소에서 읽은 값 |
| 팝업 상태 | `your-wallet-popup-v1` port(기존 `onConnect`, `onMessage` 리스너 추가 없음). 봉투 v1에 ping이 없으므로 background가 마지막으로 관찰한 상태: 연결됨/확인 중/연결 안 됨/확인 불가. 조회가 native를 열지 않음(열면 yw-app 자동 실행) | sender가 이 확장의 `popup/popup.html`이고 탭이 아닐 때만 답함 |

## 알려진 한계 (spec/05 §2.12)

- 임시 구간(document_start 뒤 저장소 응답까지, 보통 수 ms)에 실행된 페이지 코드는 기본 플래그를 보고, 그 사이 실제 MetaMask 알림은 막히지 않는다.
- 실제 지갑이 `window.ethereum`을 non-configurable·쓰기 불가로 만들면 되찾을 수 없다. EIP-6963 밖의 경로(MetaMask SDK의 확장 통신, `window.ethereum.providers` 배열 등)는 가로채지 않는다.
- 호환 모드의 메서드 집합은 기본 모드와 같다(05 §3.1). MetaMask 전용 메서드(`wallet_watchAsset`, `wallet_addEthereumChain`, `eth_signTypedData_v3` 등)와 레거시 `send`/`sendAsync`는 지원하지 않는다(4200 또는 없음).
