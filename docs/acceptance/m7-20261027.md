## spec 수정·결정 (최소 변경)

- spec/01 §3.4-3: 가드를 `#[cfg(not(any(curve25519_dalek_backend = "serial", doc, doctest)))]`로. rustdoc은 config `rustflags`를 받지 않아 `cargo test`의 doctest 수집에서 가드가 오탐했다. `RUSTFLAGS=-Dwarnings cargo check -p yw-core`(별도 target)는 여전히 컴파일 오류(종료 101)로 막힌다.
- spec/07 §5: `SolAsset`은 v1 코드에 `Sol`만(`Spl`은 v1.1). `Base58Error`는 M1의 비엄격 오류 열거형에 엄격 변형 5개를 더한 것으로 기록.
- spec/07 §8.3: devnet USDC mint `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU`(라이브 확인). 미결 4 갱신.
- spec/07 §10·미결 5: `SOL_TRANSFER_CU_LIMIT = 600` 측정 확정(최대 450), SPL 상수는 v1.1에서 측정.
- spec/07 §13.3: `build_sol_transfer_request(intent, genesis, facts) -> Result<ApprovalDraft, DisplayError>`(표시 시각은 `intent.created_at_ms`, 표시 오류는 E-UI-001로).
- spec/07 §16: 공급자 행 실측 결과 기록(`maxRetries:0`은 M7-4에서).
- spec/04 §7: E-SOL-001–005(받는 주소 프로그램·쓸 수 없는 주소·자기 자신, 서명 전 중단, `Pending` 120 s 안내) 추가.
- spec/09 §4.4 SOL-N3: "곡선 밖 수신자 → 차단"은 spec/07 §12.1-6(고위험 L02, PDA·토큰 계정일 수 있음)과 어긋나 07을 따랐다(나머지는 차단 그대로).
- 구현 결정(명세 범위 안):
  - `SolletLegacy`(태그 5)는 구현하지 않았다(07 §3.3이 허용; 스캔은 102개). `from_parts(5, …)`·`ed25519_seed`는 `InvalidPath`.
  - A01 네트워크 필드는 `Solana devnet (테스트)` / `genesis 확인됨: <base58>` 두 줄(긴 base58이 한 줄에서 잘리지 않게).
  - 서명 시각·`consumed_at_ms`는 단조 시계, 활동·저널 `signed_at_ms`는 벽시계. 승인 대기열의 SOL 항목은 `chain_id() = 0`으로 EVM 체인 판정에서 빠진다.
  - 잠긴 동안 브로드캐스트 루프는 멈추고(저널은 잠금 해제 뒤 다시 읽음), 해제 시 제네시스부터 다시 확인한다.
  - `다시 보내기`(07 §14.3)는 결과 화면에서 그 전송이 `Expired`·`FailedOnChain`일 때만 보이고, 입력(받는 주소·금액·보내기 최대·보낸 계정)만 되살린다. `검토`부터 새 미리보기·새 intent·새 승인이다.
  - 주소 강조(07 §12.3·04 §3.3): 표시 문자열이 유효한 SOL 주소의 4자 묶음일 때만 Consolas 굵게(가운데 묶음)를 쓴다. 한 줄에 다 들어가지 않으면 보통 굵기로 줄바꿈한다.

## 알려진 차이·남은 일

- v1.1 SPL(USDC·USDT, T_SPL, ATA 생성, SPL CU 측정)은 M7 후속(07 §1) — 2026-10-28 구현: [m7-spl-20261028.md](m7-spl-20261028.md).
- M7-5 오라클 교차 확인(`tools/sol-oracle/`, solana-sdk)은 온라인 크레이트가 필요해 하지 않았다. T_SOL 골든은 sdk 벡터를 재현한 독립 구현 결과와 spec 값이 같다는 데까지 확인했다.
- `sendTransaction` `maxRetries:0` 준수는 실제 전송으로만 확인 가능(M7-4).

## 수동 체크리스트 (spec/09 §5.9, spec/07 §17.6)

### 준비

1. 저장소 루트에서 빌드한다(M7-E만 debug 빌드도 필요).
   ```powershell
   cargo build -p yw-app --release --locked
   cargo build -p yw-app --locked
   ```
2. 시험 지갑: M4에서 쓰던 지갑(`%LOCALAPPDATA%\YourWallet\v3`, 시험 니모닉 `abandon` × 11 + `about`)을 쓴다. 없으면 `기존 지갑 가져오기`로 그 시험 니모닉을 가져온다. 실제 자산이 든 니모닉은 쓰지 않는다. 이 니모닉은 공개되어 있어 다른 사람도 devnet 잔액을 옮길 수 있으므로 금액은 작게, 계정 0 대신 별도 계정 인덱스를 쓴다.
3. S10 `체인` → `Solana` → 클러스터 `Solana devnet (테스트)`. 계정 `Solana 1` 주소가 `HAgk 14Jp MQLg t6rV gv7c BQFJ WFto 5Dqx i472 uT3D Kpqk`인지 본다. `계정 추가`를 세 번 눌러 `Solana 2`(`Hh8Q…Hztb`), `Solana 3`(`7Wkt…J2jm`), `Solana 4`(m/44'/501'/3'/0')를 만든다. 아래에서 A = `Solana 4`, B = `계정 추가`로 만든 `Solana 5`(m/44'/501'/4'/0', 처음엔 devnet에 없는 새 주소).
4. 엔드포인트: 설정 → `네트워크` → `네트워크 URL`의 `Solana devnet (테스트)  (solana:devnet)` `교체` → QuickNode devnet URL 붙여넣기 → `저장`(또는 템플릿 `네트워크 URL 생성`). 메인으로 돌아와 `RPC (solana:devnet): 연결됨 (genesis 확인)`. URL 값은 이 문서·채팅·스크린샷에 남기지 않는다.
5. 로그 보기:
   ```powershell
   Get-Content "$env:LOCALAPPDATA\YourWallet\v3\logs\yw-app.log" -Tail 30
   ```
   `sol.*`·`rpc.*` 줄에 URL·호스트·주소가 없어야 한다(`net=solana:devnet`만).
6. 탐색기: `https://explorer.solana.com/?cluster=devnet`에서 서명·주소를 찾는다(읽기만).
