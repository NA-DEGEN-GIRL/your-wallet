대상: HEAD 344802f(M0–M5, M7, M8, 확장 호환 모드)의 yw-app 주 창 화면 S01–S17, 비밀 창 W01–W10, 승인 창 A01, 확장 팝업.
방법: 화면 투어(`scripts/screenshot-tour.ps1`, spec/04 §11)로 고치기 전 화면을 찍어 보고 코드(`crates/yw-app/src/ui/*`, `app_approval.rs`, `crates/yw-win/src/ui/*`)와 spec/04를 대조했다. 고친 뒤 화면은 `docs/screenshots/`에 있다.

| 맨 위가 기술적 제목 `[Sepolia 테스트넷] SepoliaETH 보내기: 0.01 SepoliaETH`이고 **무엇이 일어나는지 한 문장**이 없었다. | 정보색 "요약" 카드: "Sepolia 테스트넷에서 0.01 SepoliaETH를 아래 주소로 보냅니다." + **전체 주소**(4자 묶음) + 지갑이 아는 주석("일반 계정(EOA) · 주소록: 테스트 받는 사람") + 원래 제목(보조). 요청 예시의 "0x1234 …에게"처럼 주소를 줄이는 표현은 spec/04 §0(주소 줄임 금지, 주소 오염 대비) 때문에 쓰지 않고 "아래 주소로" + 전체 주소로 바꿨다. 문장은 표시 모델에서만 만든다(digest 밖). |
| 경고·자산 변화·상세 순서가 섞여 있고 nonce·가스 한도·maxFee/tip·예상 수수료·시뮬레이션 블록 같은 기술 필드가 모두 펼쳐져 있었다. | 순서: 요약 → 자산 변화 → 확인할 경고(+ 체크박스 1개) → 핵심 정보 → `자세히 ▸`. 접는 것은 `critical == false` 필드와 원본 데이터뿐이고 critical 필드·경고·시뮬레이션 띠는 접지 않는다. `risk ≥ High`면 펼친 채 시작. |
| 경고 띠에 등급 이름이 없었다(색만). 시뮬레이션 띠만 있는 고위험 요청은 체크박스가 자산 변화 아래에 붙어 무엇을 확인하는지 불분명. | 띠·경고마다 `고위험`·`차단`·`주의`·`정보` 태그. 띠만 있을 때도 "확인할 경고" 카드 + "맨 위의 고위험 경고를 읽고, 이해했으면 아래에 체크하세요." 상태 줄에 2초 누르기 방법 안내. |
| 메시지 서명(`personal_sign`·typed data)에도 "시뮬레이션 결과 — 결과가 없어 자산 변화를 표시할 수 없습니다"가 나와 혼란. | 메시지 서명에는 자산 변화 카드를 두지 않고, 요약 문장이 "거래를 보내지는 않지만…"/"토큰 사용 권한(permit) 같은 권한을 줄 수 있으니…"를 말한다. |
| 헤더가 "라벨: 값" 문자열, 배지가 굵은 글자 줄, 버튼이 각진 사각형. | 라벨·값 두 칸, 배지는 둥근 알약, 둥근 `거부`(보조)·`승인`(주 버튼; 무장 전 회색). 체크박스 1개·2초 누르기·digest·`can_approve`·클릭 관통 방지는 바꾸지 않았다. |

### 확장 팝업
| 문제 | 고친 방법 |
|---|---|
| 제목·구역 구분이 약하고, 연결 상태가 글자 색만, 모드 설명은 선택한 것 하나만 보였다. 경고 문구가 무엇을 하라는지 불분명("가로채기가 완벽하지 않을 수 있습니다"). | 앱과 같은 색·글꼴의 흰 머리띠와 카드, 상태 알약(성공·고위험·정보 색), 모드마다 한 줄 설명이 있는 선택 카드, 주의 색 경고 "호환 모드를 쓸 때는 실제 MetaMask·Rabby 확장을 꺼 두세요…". 동작·저장 키·메시지 형식은 그대로. |

## 3. 점검 항목별 결과

- **영어 잔재**: 사용자 문구는 모두 한국어. 남긴 영어는 식별자·고유명사(`Your Wallet`, `Solana`, `Bitcoin`, `QuickNode`, `BIP39`, `EIP-712`, `passphrase`, `chainId`, `gwei`, 로그 수준 `error/warn/info/debug`, 시뮬레이션 `auto/unsupported`)이며 기술 값은 고급 설정 또는 도움말 설명과 함께 둔다.
- **잘림**: 값·주소를 자르는 곳은 없다(spec/04 §3.3). 넓은 창은 880 DIP로 폭을 제한하고 좁은 창에서는 줄바꿈한다. 버튼 폭은 글자 폭에서 계산한다.
- **DPI**: 크기는 모두 DIP(`scale`), 글꼴은 DPI별 캐시, 버튼 모서리 반지름도 컨트롤 DPI로 환산한다. 이번 확인은 100%(96 DPI)에서 화면 투어로 했고 125–200%는 수동 확인 항목으로 남긴다.
- **다음 행동 없는 오류**: 엔드포인트 없음(E-KEY-005)에는 메인 계정 카드에 `RPC 설정하기`, 잔액을 못 읽으면 "RPC 연결을 확인하고 새로고침하세요". §7 오류 문구 자체는 코드·문구 안정성 때문에 그대로 두었다(다음 단계 후보).

## 4. 남긴 것(다음 단계 후보)

- §7 오류 문구에 "다음에 할 일"을 붙이는 작업(코드는 그대로, 문구만) — spec/09·테스트가 문구를 고정하므로 별도 변경으로.
- 버튼 마우스 올림(hover) 표시, 키보드 포커스 링 외의 상태.
- 125–200% DPI와 다크 모드(현재 라이트 전용) 시각 확인.
- 승인 창 `승인`은 창이 전경이 된 뒤 1초가 지나야 켜진다(클릭 관통 방지). 화면 투어는 백그라운드에서 돌아 회색으로 찍힌다.
