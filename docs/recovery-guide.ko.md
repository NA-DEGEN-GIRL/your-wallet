# 지갑 백업·복구 안내

이 문서는 `spec.md`가 요구하는 복구 가능한 정식 지갑의 사용자 절차를 설명합니다.
현재 실행 가능한 `demo/sepolia-wallet`은 별도의 단일 프로세스 테스트넷 지갑입니다.
이 데모는 12·24단어 영어 복구 문구 생성, 12·15·18·21·24단어 가져오기,
개인 키 가져오기와 재인증 후 내보내기, 무작위 네 단어 위치와 첫 주소 재입력 확인을
지원합니다. 다만 BIP-39 passphrase와 production Key Agent의 프로세스 격리는
아직 지원하지 않습니다. 따라서 데모 지갑에는 실제 자산을 넣으면 안 됩니다.

## 정식 지갑을 만들 때

1. 다른 사람이 화면을 볼 수 없는 오프라인 장소에서 지갑 만들기를 시작합니다.
2. 지갑 창이 아니라 별도의 보안 입력창에 새 vault 비밀번호를 두 번 입력합니다.
3. 지갑이 표시한 12개 또는 24개의 영어 복구 단어를 순서대로 종이에 적습니다.
4. 사진, 화면 캡처, 클라우드 메모, 메신저, 이메일, 암호 관리자에 복구 단어를 저장하지 않습니다.
5. 지갑이 무작위로 물어보는 단어 위치와 첫 번째 계정 주소를 종이 백업을 보고 확인합니다.
6. 확인을 통과하기 전까지 해당 지갑은 연결, 서명, 전송 기능이 잠겨 있어야 합니다.

비밀번호는 이 컴퓨터의 암호화된 vault를 여는 용도입니다. 컴퓨터를 잃어버렸을 때
지갑을 복구하는 수단은 복구 단어이며, vault 비밀번호만으로는 복구할 수 없습니다.

## 복구 연습

실제 자산을 받기 전에 다음 연습을 별도의 깨끗한 환경에서 수행합니다.

1. 원래 지갑에서 첫 번째와 두 번째 계정의 전체 주소를 종이에 기록합니다.
2. 원래 지갑을 잠그고 네트워크 연결을 끕니다.
3. 독립된 표준 BIP-39/BIP-32 도구 또는 검토된 두 번째 구현에서 복구 단어를 입력합니다.
4. 파생 경로 `m/44'/60'/0'/0/0`과 `m/44'/60'/0'/0/1`의 주소가 모두 일치하는지 확인합니다.
5. 주소가 한 글자라도 다르면 자산을 받지 말고 passphrase, 단어 순서, 파생 경로를 다시 확인합니다.
6. 연습에 사용한 환경을 안전하게 초기화하고 종이 백업은 별도 장소에 보관합니다.

복구 단어를 이 저장소의 테스트, 로그, 오류 보고서 또는 이슈에 붙여 넣지 마십시오.
지원 요청을 하더라도 정상적인 개발자나 운영자는 복구 단어를 요구하지 않습니다.

## BIP-39 passphrase를 사용하는 경우

BIP-39 passphrase는 추가 비밀번호가 아니라 완전히 다른 지갑을 만드는 입력입니다.
한 글자만 달라도 다른 주소가 나오며, 분실하면 복구 단어만으로 원래 지갑을 찾을 수 없습니다.

- passphrase 사용 여부와 보관 방법을 지갑 생성 전에 정합니다.
- 복구 단어와 passphrase를 같은 장소에 두지 않습니다.
- 복구 연습에서는 passphrase까지 포함해 두 계정 주소를 확인합니다.
- 자동 계정 탐색이 복구를 대신한다고 생각하지 않습니다.

## 분실·노출 시

- vault 비밀번호만 노출된 경우: 지갑을 잠그고 안전한 환경에서 새 vault로 이전합니다.
- 복구 단어 또는 passphrase가 노출된 경우: 기존 지갑은 영구적으로 유출된 것으로 간주하고,
  안전한 새 복구 문구로 만든 지갑에 자산을 옮깁니다.
- 컴퓨터를 분실한 경우: 다른 깨끗한 환경에서 복구하되, 기존 지갑의 미확정 거래와 nonce를
  먼저 확인한 뒤 전송합니다.
- 의심스러운 서명이나 전송이 있으면 새 서명을 만들기 전에 연결 사이트를 해제하고 모든
  보류 거래를 검토합니다.

## 구현 완료 조건

정식 복구 기능은 다음 증거가 모두 있을 때만 완료로 표시합니다.

- OS 난수로 만든 12단어와 24단어 지갑 생성
- 12·15·18·21·24단어 가져오기와 checksum 검증
- 백업 확인 전 연결·서명·전송 차단
- 재실행 후 올바른 비밀번호로만 vault 잠금해제
- 손상, 잘못된 비밀번호, 저장소 rollback의 fail-closed 처리
- 독립 구현에서 계정 0과 1 주소가 일치하는 복구 시험
- 비밀값이 로그, crash 보고서, 진단 파일에 남지 않는 검사

현재 이 항목들은 production Key Agent 수직 슬라이스에서 구현 중입니다. 완료되기 전에는
Sepolia 데모의 성공을 정식 복구 기능의 증거로 간주하지 않습니다.
