# 지갑 백업·복구 안내

## 정식 지갑을 만들 때

1. 다른 사람이 화면을 볼 수 없는 오프라인 장소에서 지갑 만들기를 시작합니다.
2. 지갑 창이 아니라 별도의 보안 입력창에 새 vault 비밀번호를 두 번 입력합니다.
3. 지갑이 표시한 24개의 영어 복구 단어를 순서대로 종이에 적습니다.
4. 사진, 화면 캡처, 클라우드 메모, 메신저, 이메일, 암호 관리자에 복구 단어를 저장하지 않습니다.
5. 지갑이 무작위로 물어보는 단어 위치와 첫 번째 계정 주소를 종이 백업을 보고 확인합니다.
6. 확인을 통과하기 전에는 보내기, 서명, 사이트 연결을 쓸 수 없습니다. 받기 주소는 볼 수 있지만,
   백업 확인을 마치기 전에는 실제 자산(특히 큰 금액)을 받지 마십시오.

비밀번호는 이 컴퓨터의 암호화된 vault를 여는 용도입니다. 컴퓨터를 잃어버렸을 때
지갑을 복구하는 수단은 복구 단어이며, vault 비밀번호만으로는 복구할 수 없습니다.

## 복구 단어로 되살아나는 것과 아닌 것

- 복구 단어(와 passphrase)로 되살아나는 것: 파생 계정 전부 — EVM `m/44'/60'/0'/0/i`,
  Solana `m/44'/501'/i'/0'`, Bitcoin `m/84'/…`(아래).
- **복구 단어로 되살아나지 않는 것: '개인키 가져오기'로 넣은 개인키 계정(EVM·Solana·Bitcoin,
  화면의 "[가져온 키]").** 이 계정은 원래 개인키로만 되살릴 수 있습니다. 가져오기 전에 그
  개인키(EVM 16진수, Solana base58 keypair 또는 solana-keygen JSON, Bitcoin WIF와 쓰던 주소 형식)를
  따로(종이 등) 보관하고, 계정을 지우기 전에는 '개인키 보기'(EVM은 설정 → 보안, Solana·Bitcoin은
  그 탭의 계정)로 내보내 두거나 자산을 파생 계정으로 옮기십시오.
- **'개인키로 시작하기'로 만든 지갑에는 복구 단어가 없습니다.** 이 지갑의 백업은 가져온 각
  개인키 그 자체입니다. 다른 PC에서는 같은 개인키를 다시 가져오거나(다른 지갑 앱 포함), 아래
  '데이터 폴더 백업'으로 옮깁니다.
- 계정 이름, 주소록, 연결한 사이트, 토큰 목록, 활동 기록(meta)과 RPC 설정은 복구 단어에 없습니다.
  필요하면 아래 '데이터 폴더 백업'을 함께 하십시오.

## 복구 연습

실제 자산을 받기 전에 다음 연습을 별도의 깨끗한 환경에서 수행합니다.

1. 원래 지갑에서 첫 번째와 두 번째 계정의 전체 주소를 종이에 기록합니다.
2. 원래 지갑을 잠그고 네트워크 연결을 끕니다.
3. 독립된 표준 BIP-39/BIP-32 도구 또는 검토된 두 번째 구현에서 복구 단어를 입력합니다.
4. 파생 경로 `m/44'/60'/0'/0/0`과 `m/44'/60'/0'/0/1`의 주소가 모두 일치하는지 확인합니다.
5. 주소가 한 글자라도 다르면 자산을 받지 말고 passphrase, 단어 순서, 파생 경로를 다시 확인합니다.
6. 연습에 사용한 환경을 안전하게 초기화하고 종이 백업은 별도 장소에 보관합니다.

### Solana

이 지갑의 Solana 계정 i는 Phantom·Solflare와 같은 경로 `m/44'/501'/i'/0'`(SLIP-0010 Ed25519)를
씁니다. 계정 0은 `m/44'/501'/0'/0'`입니다.

- Phantom: '기존 지갑 가져오기' → '복구 문구'로 같은 단어를 넣으면 계정 0, 1 … 주소가 이 지갑과
  같아야 합니다.
- Solflare: '기존 지갑 가져오기' → 복구 문구 입력 → 파생 경로 목록에서 `m/44'/501'/0'/0'`
  (Solflare 기본)을 고릅니다.
- 다른 경로(예: `m/44'/501'/0'`, 오래된 지갑의 `m/44'/501'`)에 자산이 있었다면 이 지갑의
  Solana 탭 '내 계정'에서 '다른 경로 스캔'으로 찾아 표준 계정으로 옮길 수 있습니다.
- passphrase를 썼다면 복구에 쓰는 도구에도 같은 passphrase(대소문자·공백 그대로)가 필요합니다.
  passphrase 입력을 지원하는 도구인지 먼저 확인하십시오.

### Bitcoin (BIP84)

이 지갑의 Bitcoin은 BIP84 Native Segwit(`bc1q…`) 계정 0 하나만 씁니다. 메인넷 경로는
`m/84'/0'/0'`(받기 `…/0/i`, 잔돈 `…/1/i`), testnet4는 `m/84'/1'/0'`입니다. 다른 경로
(44'·49'·86')에 있는 자산은 찾지 않습니다.

- Sparrow: 새 지갑 → `Native Segwit (P2WPKH)` → BIP39 단어 입력, 파생 경로 `m/84'/0'/0'`.
- Electrum: `Standard wallet` → `I already have a seed` → `Options`에서 `BIP39 seed` → 스크립트
  `native segwit (p2wpkh)`, 경로 `m/84'/0'/0'`.
- 복구한 도구의 받기 0번·잔돈 0번 주소가 이 지갑과 같아야 합니다. 이 지갑에서 passphrase를 썼다면
  두 도구에서도 같은 passphrase(대소문자·공백 그대로)를 넣어야 같은 주소가 나옵니다.
- 미사용 주소를 20개 넘게 연속으로 발급했다면 다른 도구의 주소 검색 범위(gap limit)를 늘려야
  이후 입금이 보입니다.
- 실제 자금이 든 복구 단어는 연습용으로 다른 앱에 넣지 않습니다. 비상 복구 때만 오프라인으로 씁니다.

복구 단어를 이 저장소의 테스트, 로그, 오류 보고서 또는 이슈에 붙여 넣지 마십시오.
지원 요청을 하더라도 정상적인 개발자나 운영자는 복구 단어를 요구하지 않습니다.

## BIP-39 passphrase를 사용하는 경우

BIP-39 passphrase는 추가 비밀번호가 아니라 완전히 다른 지갑을 만드는 입력입니다.
한 글자만 달라도 다른 주소가 나오며, 분실하면 복구 단어만으로 원래 지갑을 찾을 수 없습니다.

- 새 지갑은 passphrase를 쓰지 않습니다. passphrase는 다른 지갑에서 가져올 때만 입력합니다.
- 복구 단어와 passphrase를 같은 장소에 두지 않습니다.
- 복구 연습에서는 passphrase까지 포함해 두 계정 주소를 확인합니다.
- 자동 계정 탐색이 복구를 대신한다고 생각하지 않습니다.
- 잠금 해제 때 "passphrase가 다를 수 있습니다"가 나오면 먼저 '다시 입력'을 고르십시오.
  '이 passphrase로 계속'으로 연 지갑은 다른(빈) 지갑일 수 있어, 앱이 받기와 사이트 연결·서명을
  막고 모든 화면에 경고를 띄웁니다. 그 지갑으로 받은 자산은 그때 입력한 passphrase와 대소문자·
  공백까지 같은 값이 있어야만 다시 꺼낼 수 있습니다.

## 데이터 폴더 백업과 새 PC로 옮기기

지갑 파일은 `%LOCALAPPDATA%\YourWallet\v3` 폴더에 있습니다(설정 → 브라우저·진단·정보 →
'폴더 열기').

| 파일 | 내용 |
|---|---|
| `vault.ywv` | 암호화된 복구 단어·가져온 개인키(vault 비밀번호로 엶) |
| `meta.ywm`, `journal.ywj` | 계정 이름·주소록·연결 사이트·활동, 진행 중 거래 기록(같은 vault 키로 암호화) |
| `*.prev` | 각 파일의 직전 세대 사본. 앱이 저장할 때마다 자동으로 만듭니다 |
| `*.corrupt-<숫자>` | 앱이 복구하면서 옆으로 치워 둔 손상 파일(지우지 않음) |
| `settings.json` | 설정(비밀 아님) |
| `apikeys.dpapi` | RPC 주소·API 키. **이 Windows 사용자 계정에서만** 풀립니다 |

- **백업:** 앱을 완전히 종료한 뒤(브라우저 확장이 앱을 창 없이 실행했을 수 있으니 작업 관리자에서도
  확인) `v3` 폴더 전체를 복사합니다. 앱이 켜진 채 복사하면 쓰는 중인 파일이 섞일 수 있습니다. 이
  백업도 vault 비밀번호로만 열리지만 비밀번호를 추측하는 공격의 대상이 되므로 안전한 곳에 둡니다.
  복구 단어 종이 백업을 대신하지 않습니다.
- **`.prev` 복구:** 지갑 파일이 손상되면 앱이 '이전 사본으로 복구'를 제안합니다. 비밀번호가
  맞는데도 계속 열리지 않으면, 잠금 화면에 나타나는 '이전 사본(.prev)으로 복구'를 같은 비밀번호로
  시도할 수 있습니다(파일이 정상이면 복구하지 않고 그대로 엽니다). 복구하면 마지막 변경(예: 방금
  가져온 개인키)이 빠질 수 있으니 확인하십시오.
- **새 PC로 옮기기:** 새 PC에 앱을 설치하고, 앱이 실행 중이면 종료합니다. 복사해 둔
  `vault.ywv`·`meta.ywm`·`journal.ywj`(와 각 `.prev`)를 새 PC의 `%LOCALAPPDATA%\YourWallet\v3`에
  넣고 실행해 원래 vault 비밀번호로 엽니다. 새 PC에서 이미 다른 지갑을 만들었다면 그 파일과 섞지
  말고 먼저 다른 곳으로 옮기십시오(앱은 지갑 파일을 덮어쓰거나 지우지 않습니다). `apikeys.dpapi`는
  다른 PC·다른 Windows 사용자에서 풀리지 않으므로 RPC 주소·API 키는 설정에서 다시 넣습니다. 폴더를
  옮길 수 없으면 복구 단어로 '기존 지갑 가져오기'를 하고(복구 단어가 없는 지갑은 '개인키로
  시작하기'), 가져온 개인키 계정은 원래 개인키로 다시 가져옵니다.
- **업그레이드 전:** 새 버전을 설치하기 전에 앱을 종료하고 `v3` 폴더를 먼저 백업합니다. 새 버전이
  파일 형식을 바꾸더라도 원래 파일로 돌아갈 수 있게 하기 위해서입니다. 업그레이드 뒤 첫 실행에서
  잠금 해제와 주소가 이전과 같은지 확인하십시오.

## 분실·노출 시

- vault 비밀번호만 노출된 경우: 지갑을 잠그고 안전한 환경에서 새 vault로 이전합니다.
- 복구 단어 또는 passphrase가 노출된 경우: 기존 지갑은 영구적으로 유출된 것으로 간주하고,
  안전한 새 복구 문구로 만든 지갑에 자산을 옮깁니다.
- 컴퓨터를 분실한 경우: 다른 깨끗한 환경에서 복구하되, 기존 지갑의 미확정 거래와 nonce를
  먼저 확인한 뒤 전송합니다.
- 의심스러운 서명이나 전송이 있으면 새 서명을 만들기 전에 연결 사이트를 해제하고 모든
  보류 거래를 검토합니다.
