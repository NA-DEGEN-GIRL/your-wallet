### 2. 고친 것 (전 → 후)

- **1-1 S08 한 번에 RPC 연결**: 전 — S08은 `RPC 설정하기`로 설정 화면에 보내고, 거기서 이름·토큰 두 칸 → `저장` → `네트워크 URL 생성` → 오버레이 `생성` → 네트워크마다 `테스트`를 눌러야 했다. 후 — 엔드포인트가 0개이고 공급자가 QuickNode이면 S08 카드에 "QuickNode 주소" 칸 하나(`ES_PASSWORD`, 주소 전체가 들어가는 폭)와 `연결하기`, 링크 `알케미·직접 입력은 설정에서 ▸`. `연결하기`는 기존 함수만 차례로 부른다: `read_wiping` 뒤 곧바로 칸 비우기 → `quicknode_input`(한 칸에 주소 전체; 빈 값 "주소를 붙여넣으세요.", 형식 오류는 같은 자리에 E-KEY-002) → `set_quicknode` → `save_apikeys`(DPAPI) → 덮어쓰기 없는 `generate`(S08에는 덮어쓸 주소가 없어 T-RPC-GENERATE 없음) → 만든 네트워크 모두 순차 테스트 큐. 결과는 같은 카드에 네트워크마다 한 줄(✓ / ✗는 오류 띠와 §7 문구, 그 행을 여는 링크 / "… 테스트 중")과 "13개 중 11개 작동", ✗가 있으면 대시보드에서 그 체인을 켜고 "모두 테스트"로 다시 확인하라는 안내. rpc.json이 있으면 링크 `rpc.json이 있습니다 — 설정에서 가져오기 ▸`(그 카드로 스크롤). 알케미·직접 입력이면 지금처럼 설정으로 보내는 버튼만. 로그는 `tpl.saved template=quicknode`·`rpc.generated net=…`·`rpc.test net=… result=…`뿐. 시험 `first_setup_connects_quicknode_in_one_step`.
- **1-2 '처음 설정' 체크리스트**: 전 — 제목 "마지막 단계: 블록체인 연결(RPC)" 카드와 `나중에`, 카드 밖 확장 링크, RPC가 있으면 `지갑 열기`만. 후 — 카드 "처음 설정" 하나에 ① 블록체인 연결(RPC)(1-1의 칸, 주소가 이미 있으면 "RPC 주소 n개 · 이번 실행 테스트: 작동 a · 실패 b"와 `RPC 설정 열기`), ② dApp 연결(선택, 둘 중 하나: Chrome 확장 상태 + `설치 방법`(S23, `← 돌아가기`가 S08로) / WalletConnect "Project ID 없음·설정됨" + `설정`(S13)), ③ 첫 입금 시험("실제 자산은 소액으로 받기 → 보내기를 한 번 해 보세요. EVM 탭은 Sepolia 테스트넷으로 시작합니다." + `받기`). `지갑 열기`는 RPC가 없어도 늘 맨 아래. S08에서 연 설정 → 네트워크(RPC)와 S13은 맨 위 링크가 `← 처음 설정으로`(`App::back_row`, 새 플래그 `done_return`)이고 S08로 돌아온다. S08 플래그(`done_imported`·`done_start`·`done_yubikey`·`done_return`·연결 결과)는 `지갑 열기`·`← 메인으로`·잠금에서만 지운다. 가져오기·개인키로 시작 뒤에는 정보 카드 "잔액이 안 보이면": Sepolia로 시작한다는 줄 + `Ethereum 메인넷으로 보기`(네트워크 칩과 같은 `evmChainId` 저장), 계정을 자동으로 찾지 않으니 "내 계정 → 계정 추가"·Solana "다른 경로 스캔"(가져오기만), Bitcoin·Zcash가 꺼져 있으면 그 줄(꺼진 것만).
- **1-3 RPC 공급자 카드**: 전 — `저장`(주) · `네트워크 URL 생성` · `자격 정보 삭제`(늘 켜짐, 확인 없음), 생성은 늘 덮어쓰기 오버레이, 빈 칸이면 E-KEY-004. 후 — 주 `저장하고 RPC 주소 만들기`, 보조 `자격 정보만 저장`(저장 뒤 이 템플릿 대상에 주소가 없으면 "RPC 주소는 아직 없습니다 — “저장하고 RPC 주소 만들기”를 누르세요."), 위험 `자격 정보 삭제`(저장된 것이 있을 때만, 1-6 확인). 덮어쓰기 오버레이는 대상 중 이미 주소가 있는 네트워크가 있을 때만(덮어쓰기 기본 끔 그대로), 없으면 바로 만든다. 칸이 비어 있고 저장된 것도 없으면 E-KEY-004 대신 "위 칸에 엔드포인트 이름과 토큰(또는 주소 전체)을 넣으세요." 생성 안내 "RPC 주소 n개를 만들었습니다. 연결을 확인하는 중입니다 — 결과는 아래 각 행에 나옵니다."(건너뛴 네트워크가 있을 때만 "템플릿 항목이 없는 m개는 직접 입력하세요: …"). QuickNode 도움말에 쓸 체인을 엔드포인트에 하나씩 켜야 한다는 줄, rpc.json이 있으면 카드 첫 줄 안내.
- **1-4 테스트 큐·요약·3상태**: 전 — `테스트`는 네트워크마다 직접, 생성·교체·가져오기 뒤 결과 없음, "테스트 중…"이 빨간 오류 띠. 후 — `App::rpc_tests`(`VecDeque<NetworkId>`, 중복 없음): `RpcEvent::Test` 답이 올 때마다 다음 `RpcJob::Test` 하나만 보낸다(FIFO 작업자가 잔액·보내기 작업을 오래 막지 않게). "네트워크별 RPC 주소" 머리에 "RPC 주소 11/13개 설정 · 이번 실행 테스트: 작동 9 · 실패 1 · 안 함 1", 실패한 네트워크 이름 링크(새 ID 범위 16,720–16,783), `모두 테스트`(도는 동안 꺼진 `테스트 중 3/11`). 자동 테스트: `generate`·`save_replacement`·`finish_rpc_import`가 쓴 네트워크(가져오기 안내도 "연결을 확인하는 중입니다 — 결과는 아래 각 행에 나옵니다."). `rpc_messages`는 3상태(`TestState`: 테스트 중 = 정보, 작동 = 완료, 실패 = 오류 색), 설정 → Bitcoin `Esplora URL` 테스트도 같다. 요청 내용(eth_chainId·getGenesisHash·getblockchaininfo·getblockhash 0, 주소 없음)과 로그는 그대로, EVM 테스트 범위도 넓히지 않았다.
- **1-5 그 네트워크 행으로 바로**: `App::open_rpc_row(network, edit)` — 설정 → 네트워크(RPC)를 열고 그 행의 컨트롤을 보기 안으로 스크롤(`app_scroll::reveal_control`을 `pub(crate)`로), `edit`면 `replace_target`으로 입력 칸(`ES_PASSWORD` 그대로)을 열고 포커스, 아니면 그 행의 `테스트`에 포커스. EVM·Solana·Bitcoin(게이트)·Zcash 탭의 `RPC 설정하기`는 탭별 새 ID로 그 탭의 지금 네트워크를 `edit`로 연다. 설정 탭 `네트워크(RPC)`·`네트워크(RPC) 설정으로`·S08 `RPC 설정 열기`는 그대로 맨 위. 템플릿 자격 정보가 저장되어 있고 그 네트워크에 템플릿 항목이 있으면 열린 칸 위에 "{QuickNode|알케미} 자격 정보가 저장되어 있습니다 — 위 “저장하고 RPC 주소 만들기”로 비어 있는 주소를 한 번에 만들 수 있습니다." S08 ✗ 줄과 요약의 실패 이름은 `edit` 없이 연다.
- **1-6 지우기 확인**: 네트워크 행 `삭제` → `Confirm::RpcUrlDelete(NetworkId)`("RPC 주소 지우기": "{이름} ({NetworkId})의 RPC 주소를 지웁니다. 저장된 주소는 다시 볼 수 없어, 다시 쓰려면 “저장하고 RPC 주소 만들기”({공급자} 자격 정보: 설정됨/없음) 또는 “입력”으로 다시 넣어야 합니다. 이 네트워크에 확정 전 거래가 있으면 주소를 다시 넣을 때까지 상태 확인이 멈춥니다."), `자격 정보 삭제` → `Confirm::TemplateDelete`(끝 "…이미 만든 네트워크별 RPC 주소는 그대로이고, 새 체인 주소를 만들 때 다시 넣어야 합니다."), AI 설명 `키 삭제` → `Confirm::LlmKeyDelete`(끝 "…AI 설명을 다시 쓰려면 키를 다시 넣어야 합니다."). 버튼 `지우기`(위험)·`취소`. 지운 뒤 그 행이나 카드에 완료 띠. 지우는 함수·저장·E-APP-002 처리는 그대로이고 확인만 더했다.

### 2. 고친 것 (전 → 후)

- **2-1 EVM 잔액 바로 다시 읽기**: 전 — Solana는 계정·탭이 바뀌면 다음 틱에 다시 읽었지만 EVM은 네트워크 칩·계정 선택 뒤에도 60초 주기를 기다렸다(그동안 이전 네트워크·계정 기준의 표시). 후 — `App::evm_balances_due`(`next_balance_ms = 0`)를 네트워크 칩(`on_indexed_command`, `save_settings` 다음)과 S08 `Ethereum 메인넷으로 보기`, 계정 선택(`select_account`), 계정이 늘어난 결과(`KeyOutcome::Addresses`·`MnOutcome::Derived` — 첫 복구 단어와 추가 복구 단어 —, 가져온 EVM 키 두 경로, meta 다시 읽기로 오는 YubiKey 계정), HyperCore 카드의 `HyperEVM에서 Core로 이동`(`evmChainId` 저장), 추적 결과에 `Included`·`Finalized`·`Dropped`가 있을 때, 그리고 그 네트워크의 RPC 테스트가 작동했을 때 부른다. S10에서는 `evm_tick`이 다음 틱(≤ 250 ms)에 `refresh_balances`를 부른다. 시험 `chip_and_account_changes_read_balances_at_the_next_tick`.
- **2-2 토큰 잔액의 소유자**: 전 — `BalanceSnapshot`의 토큰 잔액은 작업을 보낼 때의 선택 계정 것인데, 계정을 바꾸면 다음 읽기 전까지 새 계정의 토큰 잔액처럼 보였다(토큰 카드, "토큰: …" 줄, S11 보유량, `{기호} 보내기`). 후 — `BalanceSnapshot.token_owner`(작업자가 `RpcJob::Balances`의 `token_owner`로 채움); `App::token_balance`는 그것이 지금 선택한 계정이 아니면 없음 — 토큰 카드 "잔액 알 수 없음", 선택 계정 카드의 "토큰: …" 줄 빠짐, S11 자산 라디오 "· 잔액 모름", `{기호} 보내기` 꺼짐. 2-1 덕분에 새 계정의 값은 다음 틱에 온다. 시험 `token_balances_of_another_owner_are_unknown`.
- **2-3 잔액 세 상태와 RPC 실패 안내**: 전 — 큰 잔액 아래 "블록 N 기준 · 갱신 실패 E-RPC-003", 상태 줄 "오류 E-RPC-003"으로 코드만 보였고 무엇을 해야 하는지 없었다; 값이 없으면 "잔액을 아직 읽지 못했습니다. RPC 연결을 확인하고 새로고침하세요."뿐. 후 — `BalanceState.updated_unix_ms`·`SolUi::balance_at`에 결과를 받은 시각을 남기고 큰 잔액 아래를 세 상태로: 결과가 아직 없으면 "잔액을 불러오는 중…", 성공이면 "블록 N 기준 · HH:MM 갱신"(Solana는 블록 번호가 없어 "… lamports · RPC finalized 기준(참고) · HH:MM 갱신"), 실패이면 네트워크 카드에 '오류' 띠 하나 — 그 코드의 §7 전체 문구(`ErrorCode::text`)에 이전 값이 있으면 "아래 잔액은 블록 N에서 마지막으로 읽은 값입니다."(Solana "HH:MM에") — 와 버튼 `이 네트워크 RPC 테스트`(배치 1과 같은 큐의 `RpcJob::Test`, 결과는 같은 카드에 3상태 띠, 작동하면 다음 틱에 다시 읽음)·`RPC 설정 열기`(`open_rpc_row(network, false)`). 선택 계정 카드는 "잔액을 읽지 못했습니다 — 위 네트워크 카드의 안내를 보세요."이고 이전 값은 흐리게(새 `Item::DisplayMuted`) 둔다. 상태 줄은 "오류 E-RPC-003 · 인증 거부"(`ErrorCode::short_name`, E-RPC-001–010, spec/04 §7 표에 "짧은 이름"). 띠에는 네트워크 이름만(URL·호스트 없음, §1.9). 주소 없음(U17)과 차단 상태는 그대로이고, 알 수 없는 체인(E-APP-009)은 "불러오는 중"에 머물지 않고 실패 띠로 보인다. 새 시험 없음(문구를 단언하던 시험도 바뀌지 않았다).
- **2-4 Solana 메인넷 띠 한 겹**: 전 — `main_screen`의 Solana 분기가 T-MAINNET을 넣고 `sol_main_screen`의 `sol_cluster_banner`가 또 넣어(11-08 회귀) 두 겹. 후 — 분기의 세 줄을 지워 `sol_cluster_banner` 하나만. S11·S12는 원래 한 겹. 시험 `backup_discard_mainnet_and_done_texts`에 Solana mainnet S10·EVM 메인넷 S10(1, 999)의 T-MAINNET 띠가 정확히 1개인지 세는 단언을 더했다.
- **2-5 같은 이름의 계정 구분**: 전 — 복구 단어마다 첫 계정이 "계정 1"(Solana "Solana 1")이라 목록 밖(선택 계정 카드, S11, S12, 활동)에서는 어느 것인지 알 수 없었고, 첫 복구 단어 계정의 경로만 "m/44'/60'/0'/0/i"였다. 후 — 복구 단어가 둘 이상이면 그 자리들의 이름에 `mnemonic_tagged`("계정 1  [복구 단어 2]")를 쓴다(EVM `evm_account_title`·`evm_pref_title`, Solana `sol_title`; Solana S11은 이전부터). 첫 복구 단어 계정의 경로 줄은 "{첫 복구 단어 라벨} · m/44'/60'/0'/0/{i}"(`evm_path_text`, S10·S12). 새 계정의 기본 이름은 모든 복구 단어를 통틀어 겹치지 않는다: EVM "계정 {지금 있는 “계정 N” 중 최댓값 + 1}"(`Meta::next_evm_number`, 가져온 키·YubiKey 계정 이름도 센다), Solana "Solana {…}"(`Meta::next_sol_label`) — `KeyOutcome::Addresses`(앱이 번호를 `workers::key::new_account(index, number, address)`에 넘긴다), `MnOutcome::Derived`, Solana `계정 추가`·추가 복구 단어 계정·스캔에서 더하기, key worker의 meta 맞추기(추가 복구 단어의 첫 EVM·Solana 계정; 문서 전체와 그 자리에서 만든 항목을 센다). 이미 저장된 이름은 그대로. 각 복구 단어의 첫 계정에서 `숨기기`가 꺼져 있으면 도움말 "각 복구 단어의 첫 계정(…/0)은 숨길 수 없습니다."(EVM·Solana). 새 시험 없음.
- **2-6 EVM 토큰 보내기의 단위와 수수료**: 전 — 금액 칸 라벨 "금액"(단위 없음), 도움말 "'최대'는 수수료를 뺀 잔액 전부입니다."가 토큰에도 나왔고(토큰은 수수료를 빼지 않는다), 수수료를 낼 ETH가 없으면 "잔액이 부족합니다(수수료 포함)"만 보였다. 후 — 라벨 `금액 ({기호})`, 도움말은 기본 자산 "'최대'는 수수료를 뺀 잔액 전부입니다." / 토큰 "'최대'는 이 토큰 잔액 전부입니다. 수수료는 {네이티브}로 따로 냅니다.", 기본 자산 라디오에도 보유량("SepoliaETH · 1.25" / "· 잔액 모름"), 토큰이면 수수료 줄 "예상 최대 수수료: {x} {네이티브} (보유 {y} {네이티브})", `check_funds`의 E-INP-012가 네이티브 수수료 부족이면(토큰 금액 ≤ 토큰 잔액) 그 띠 아래 "수수료를 낼 {네이티브}이(가) 부족합니다 — 이 계정에 {네이티브}을(를) 먼저 받으세요." §7 문구·코드·검사·검토·승인 규칙은 그대로. 새 시험 없음.
- **2-7 활동 목록 맞추기**: 전 — Zcash 행만 `Field` 한 줄("보냄 X ZEC" | "상태 · 수수료 n zats · 받는 주소 … · 만료 높이 …", 시각 없음), 받는 주소가 EVM·Solana는 도움말 글자, Bitcoin·Zcash는 제각각, 주소록·내 계정 주석은 EVM만, Ethereum·Sepolia에는 `탐색기 링크 복사`가 없었다. 후 — Zcash 행은 "{YYYY-MM-DD HH:MM} · 보냄 {X} ZEC"(`signed_at_ms`, 로컬 시각) / "상태: …"(만료 높이는 미확정일 때만) / "받는 주소"와 `Mono` 4자 묶음 전체 / "수수료 0.0001 ZEC"(zats를 ZEC로) / txid. 받는 주소 줄은 모든 체인에서 "받는 주소{주석}" + `Mono` 묶음이고, Solana·Bitcoin에도 표시 전용 " → 주소록: {이름}"·" → 내 계정: {라벨}"(Zcash는 주소록이 없어 내 계정만). yw-core `chain.rs` 탐색기: Ethereum 메인넷 `https://etherscan.io`, Sepolia `https://sepolia.etherscan.io`, HyperEVM은 spec에 공식 탐색기가 없어 그대로 없음(spec/03 §1 표). `탐색기 링크 복사`는 지금처럼 `{explorer}/tx/{hash}`를 복사만 한다(§2.14). 활동 주소에 복사·선택 버튼을 두지 않는 규칙 그대로, EVM 외 활동 접기는 하지 않았다. explorer 없음을 단언하던 시험은 없었다.
- **2-8 HyperCore 카드 접기**: 전 — Sepolia·Base 같은 체인을 볼 때도 HyperCore 카드(빨간 메인넷 띠, 라디오, 버튼 6개)가 늘 펼쳐져 화면을 차지하고, 위 EVM 테스트넷 띠와 함께 띠가 둘이었다. 후 — `hc_foldable`: 선택한 EVM 체인이 999·998·42161·421614가 아니고, 선택 계정의 HyperCore 활동이 서명 중·전송 중이 아니고, 이번 실행에서 펼친 적이 없으면 접힌 카드 — 배지와 "Hyperliquid HyperCore 메인넷 · 계정 가치 1,234.56 USDC · 현물 3종"(불러오기 전·불러오는 중·실패는 그 상태 한 줄, 테스트넷은 "HyperCore 테스트넷"), 링크 `펼치기 ▸`. 접힌 카드에는 동작 버튼도 띠도 없다. 펼치면 지금 카드 그대로에 `접기 ▴`. 동작 버튼을 그리는 곳에는 언제나 네트워크 띠도 그린다. 60초 잔액 읽기는 그대로, 펼친 상태는 메모리에만(`HcUi::unfolded`). 링크 ID 13,494–13,495(HyperCore 범위, `ui::command_ids`에 등록), spec/11 §8에 한 줄. 시험 `the_hypercore_card_folds_next_to_other_chains`(기존 `card_activity_is_the_selected_accounts`는 HyperEVM에서 보도록 고쳤다).
- **2-9 Bitcoin 수수료 미리 보기**: 전 — 빠름·보통·느림이 무엇인지(대기 시간·sat/vB) 몰랐고, 수수료 하한·예상 수수료는 `검토`(계획) 뒤에야 보였다. 후 — 읽기 전용 `BtcRpcJob::FeeQuote { job, target, chain }`: `Refresh`와 같은 세션 체인 확인(`ensure_chain`) 뒤 `get_mempool_info`(하한)와 `estimate_smart_fee` 2·6·24(economical)를 기존 cap·파서로 읽어 `BtcRpcEvent::FeeQuote { floor, rates: [Option<FeeRate>; 3] }`. 주소를 보내지 않고 계획·승인·UTXO 예약도 없다. 보내는 때: 폼을 열 때, 사용자 `새로고침` 때, 견적이 60초보다 오래된 상태에서 수수료 라디오를 바꿀 때. 라디오 "빠름 · 약 20분 · 12 sat/vB" / "보통 · 약 1시간 · 8 sat/vB" / "느림 · 약 4시간 · 3 sat/vB"(하한보다 낮은 추정은 하한 — `choose_fee_rate`와 같다, 추정이 없으면 "· 추정 없음", 불러오는 중이면 줄 "수수료 추정을 불러오는 중…"). 금액과 받는 주소가 유효하면 "예상 수수료 약 1,692 sats (0.00001692 BTC) — 입력 1개·출력 2개(받는 사람·잔돈) 기준입니다. UTXO를 여러 개 쓰면 늘어납니다. 실제 수수료는 검토에서 다시 계산해 승인 창에 보입니다."(vsize = `estimate_weight_with(계정 input_weight, 1, [받는 주소 spk, 잔돈 spk])`, 로컬 계산), 상한(500 sat/vB·0.005 BTC)을 넘으면 주의 "이 수수료율은 상한을 넘어 검토 뒤 수수료(sats)를 직접 입력해야 합니다." "수수료 하한 …" 줄도 견적의 하한으로 검토 전에 채운다. "주소 종류: P2WPKH" → "주소 종류: 네이티브 세그윗 (P2WPKH)"(다른 형식도 쉬운 이름 먼저; 승인 창의 `type_label`은 그대로). `검토`(Prepare)는 지금처럼 추정과 하한을 새로 읽고 견적을 쓰지 않는다. 상한·typed-fee 해제·승인 창 표시 그대로. spec/08 §8.2. 새 시험 없음(기존 파서·cap을 다시 쓴다).
- **2-10 스크롤**: 전 — 체인 탭을 바꿔도 이전 탭의 스크롤 위치가 그대로라 새 탭의 네트워크 띠가 화면 밖일 수 있었고, `← 메인으로`·`취소`·오버레이 `취소`는 늘 맨 위로 돌아갔고, DPI가 바뀌면 같은 픽셀 값이 다른 위치였다. 후 — 탭 클릭과 Ctrl+1–4(`TAB_EVM`, `sol/btc/zec_select_tab`)는 `tab_top`: 떠나는 탭의 위치를 적고 scroll 0, `stop_scroll`. `app_scroll::ScrollMemory`가 이번 실행 동안 S10 탭별·설정 구역별·S08·S13·S14의 마지막 위치(DIP)를 기억하고, 돌아오는 길(`App::return_to`: `← 메인으로`, S23 `← 돌아가기`, `← 처음 설정으로`, 보내기·수수료 올리기·S-HC `취소`)로 들어오면 내용 높이로 잘라 복원한다. 확인 오버레이는 아래 화면의 위치를 적어 두었다가 `취소`나 확인 뒤 그 화면으로 돌아오면 거기로. 새로 들어가는 화면, 오버레이, 탭 전환, 잠금 뒤에는 맨 위(잠그면 기억을 지운다). `Msg::DpiChanged`는 scroll에 새 DPI / 옛 DPI를 곱한다(마지막 배치의 DPI를 기억). 위험 표시는 그대로이고 탭에 들어가면 띠가 먼저 보인다. 시험 `a_chain_tab_opens_at_its_top`.
- **2-11 F5·Ctrl+,·Esc와 설정 구역 기억**: 전 — 주 창에는 Ctrl+L·Ctrl+1–4·탐색 키만 있었고 Esc(`IDCANCEL`)·Enter는 아무것도 하지 않았으며 `설정`은 늘 `보안`으로 열렸다. 후 — 관찰자(VK_L 옆)가 F5와 Ctrl+,를 `WM_YW_SHORTCUT`(`events::Shortcut`)으로 post. F5는 S10이고 주 창이 앞이고 비밀 창이 없고 버튼이 켜져 있을 때만 보이는 탭의 `새로고침`을, Ctrl+,는 `설정` 버튼을 Ctrl+1–4와 같은 경로(`press_shown`: 보이고 켜진 컨트롤을 클릭처럼)로 누른다. 주 창의 `IDCANCEL`(Esc): `Screen::Confirm`이면 `CONFIRM_NO`와 같은 경로, 열린 인라인 편집(이름 바꾸기 — EVM·Solana 계정과 복구 단어, RPC `교체`, 주소록 저장 프롬프트, S14 항목 편집)이면 그 편집 취소, 뒤로 링크가 있는 화면(S11·S12·S13·S14·S15·S16·S23·S-HC, Solana·Bitcoin 보내기·받기)이면 그 링크(입력은 지우지 않는다). S17, YubiKey 마법사·관리 흐름(설정 → YubiKey의 관리 흐름 포함), S22, 처리 중, 첫 실행 화면, 비밀 창이 열린 동안은 무시. `IDOK`(Enter)는 그대로 무시. `설정` 버튼과 Ctrl+,는 이번 실행에서 마지막으로 연 구역으로(처음은 보안, `App::settings_last`). 설정 → 브라우저·정보 단축키 줄에 "F5 새로고침 · Ctrl+, 설정 · Esc 뒤로·취소". 승인 창(Enter 무시, Esc = 거부)과 비밀 창 규칙 그대로. 새 시험 없음.
- **2-12 주 창 위치·크기 기억**: 전 — 늘 960×680 가운데로 열려, 큰 모니터에서는 매번 키우고 옮겨야 했고 최대화도 기억하지 않았다. 후 — 데이터 폴더의 새 `window.json`(`window_state`): `{"v":1,"x","y","w","h","max","dpi"}` — `GetWindowPlacement` `rcNormalPosition`(화면 픽셀로 바꿈), 최대화, 저장 때 DPI. `settings.json`에 두지 않은 이유: `save_settings`가 `guard.pending`을 지우고 읽기 전용 설정이면 쓸 수 없다. 쓰는 때: `WM_EXITSIZEMOVE`(yw-win 새 `Msg::ExitSizeMove`)·`WM_SIZE`·DPI 변경 뒤 주 타이머로 1초 디바운스, 종료 때 — 바뀌었을 때만 `atomic_write`. 시작할 때 `read_limited_no_reparse`(≤ 256 B) + yw-json 엄격 파싱과 범위 검사, 그 사각형이 걸친 모니터(`MonitorFromRect`, `MONITOR_DEFAULTTONULL`)의 작업 영역과 160×120 DIP 이상 겹칠 때만 쓴다: DPI가 다르면 크기를 비율로 환산하고 최소 크기·작업 영역으로 잘라 그 모니터로 옮긴 뒤 같은 사각형을 한 번 더 적용(DPI 변경의 제안 사각형을 덮는다), `max`면 첫 표시를 `SW_SHOWMAXIMIZED`. 겹치지 않으면 기본 배치 — 파일이 없을 때의 기본 크기는 960 × clamp(작업 영역 높이 DIP − 96, 680, 900), 가운데. `--background`도 같은 사각형. 보안 스냅샷·지갑 초기화 대상 아님. yw-win에 placement 래퍼(`Window::{placement, monitor_area, outer_size, set_outer_rect, show_maximized}`, `ui::monitor_for_rect`; 이미 켠 windows-sys 기능만, unsafe는 yw-win 안에만). 투어와 화면 시험은 `place_main_window`를 부르지 않아 960×680 고정. 시험(순수 함수) `a_saved_place_off_every_monitor_goes_to_the_default_place`. spec/04 §1.7·§9.
- **2-13 빌드 확인(커밋)**: 전 — 설정 → 정보에는 버전(0.3.0)만 있어 어느 커밋을 설치했는지 화면·로그로 알 수 없었다. 후 — `build_info`: 실행 파일 옆 `yw-install.json`을 `read_limited`(≤ 64 KiB)와 엄격 JSON으로 읽어 `commit`이 `^[0-9a-f]{7,40}$`일 때만 쓰고(다른 필드·해시는 읽지 않는다) "버전 0.3.0 · 커밋 75c3136a1b2c"(앞 12자), 파일이나 값이 없으면 "0.3.0 · 설치 기록 없음 — 개발 빌드". `app.start` 로그에도 같은 검사를 통과한 값만 `commit=`(새 `Field::Commit`, 형식이 틀리면 `?`). 알림 기록·띠별 닫기·진단 요약 복사는 하지 않았다. 시험(순수 파서) `a_malformed_commit_is_dropped`.

### 3. 남긴 것과 이유·대안

- **D1 `{기호} 보내기`는 숨기지 않고 끈다**(2-2): 제안은 "잔액 > 0일 때만 보임 → 숨는다"였지만 지금 규칙(spec/04 §2.6, Solana 토큰 카드와 같음)은 링크를 늘 그리고 잔액 > 0일 때만 켠다. 소유자가 다른 스냅샷이면 잔액이 없음이 되어 링크가 꺼지므로 누를 수 없다는 결과는 같고, Solana 카드와의 일관성을 지켰다.
- **D2 Ctrl+,는 `설정` 버튼이 보일 때만**(2-11): F5와 같은 "그 컨트롤이 보이고 켜져 있을 때 누른다" 경로라 상단 막대가 있는 S10에서만 동작한다. 다른 화면에서 설정으로 뛰면 입력 중인 폼을 떠나게 되어 이번에는 넓히지 않았다.
- **D3 Bitcoin 계정 이름**(2-5): 0부터 세는 기본 이름과 이름 바꾸기는 BTC meta에 필드가 필요해 하지 않았다(항목 범위). Bitcoin 활동의 " → 내 계정: …"은 지금 계정 이름("네이티브 세그윗 계정 0")을 쓴다.
- **D4 Solana에는 블록 번호가 없다**(2-3): Solana 잔액 응답에서 slot을 받지 않아 성공 줄은 "… RPC finalized 기준(참고) · HH:MM 갱신", 실패 띠의 끝은 "아래 잔액은 HH:MM에 마지막으로 읽은 값입니다."로 바꿔 썼다.
- **D5 수수료 미리 보기의 범위**(2-9): 수수료 올리기 폼과 Zcash 예상 수수료는 하지 않았다(항목 범위). 보내기 최대는 UTXO 여러 개·잔돈 없음이라 "입력 1개·출력 2개" 예상이 맞지 않아 예상 수수료 줄을 보이지 않는다.
- **D6 스크롤을 기억하는 화면**(2-10): 목록의 화면(S10 탭별·설정 구역별·S13·S14)과 `← 처음 설정으로`가 돌아가는 S08만 기억한다. S11·S12·S-HC 같은 폼은 늘 맨 위에서 연다. S17의 `취소`는 돌아오는 길 목록에 없어 그대로 맨 위다.
- **D7 다중 모니터·혼합 배율의 실기 확인**(2-12): 이 PC에서는 순수 함수 시험과 단일 모니터 실행만 했다. 다른 DPI 모니터로 옮긴 위치의 복원(같은 사각형 두 번 적용)은 다음 수동 확인 때 본다. 승인 창 배치는 배치 3에서 다룬다.
- **D8 알림 기록·띠별 닫기·진단 요약 복사**(2-13): 항목대로 하지 않았다.
- **D9 화면 투어**: 바뀐 장면만 다시 찍었다. 02·08·24·25·32는 스크롤 막대가 늘 보이기 전(960 폭)의 사진이고 29는 배치 1 이전의 스크롤 위치지만 내용이 같아 이번에도 다시 넣지 않았다. 12·13·22·23·39·42·44·09는 경과 시간·카운트다운 같은 시각 값만 달라 넣지 않았다.
