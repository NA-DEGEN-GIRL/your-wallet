### 2. 고친 것 (전 → 후)

- **1-1 S08 한 번에 RPC 연결**: 전 — S08은 `RPC 설정하기`로 설정 화면에 보내고, 거기서 이름·토큰 두 칸 → `저장` → `네트워크 URL 생성` → 오버레이 `생성` → 네트워크마다 `테스트`를 눌러야 했다. 후 — 엔드포인트가 0개이고 공급자가 QuickNode이면 S08 카드에 "QuickNode 주소" 칸 하나(`ES_PASSWORD`, 주소 전체가 들어가는 폭)와 `연결하기`, 링크 `알케미·직접 입력은 설정에서 ▸`. `연결하기`는 기존 함수만 차례로 부른다: `read_wiping` 뒤 곧바로 칸 비우기 → `quicknode_input`(한 칸에 주소 전체; 빈 값 "주소를 붙여넣으세요.", 형식 오류는 같은 자리에 E-KEY-002) → `set_quicknode` → `save_apikeys`(DPAPI) → 덮어쓰기 없는 `generate`(S08에는 덮어쓸 주소가 없어 T-RPC-GENERATE 없음) → 만든 네트워크 모두 순차 테스트 큐. 결과는 같은 카드에 네트워크마다 한 줄(✓ / ✗는 오류 띠와 §7 문구, 그 행을 여는 링크 / "… 테스트 중")과 "13개 중 11개 작동", ✗가 있으면 대시보드에서 그 체인을 켜고 "모두 테스트"로 다시 확인하라는 안내. rpc.json이 있으면 링크 `rpc.json이 있습니다 — 설정에서 가져오기 ▸`(그 카드로 스크롤). 알케미·직접 입력이면 지금처럼 설정으로 보내는 버튼만. 로그는 `tpl.saved template=quicknode`·`rpc.generated net=…`·`rpc.test net=… result=…`뿐. 시험 `first_setup_connects_quicknode_in_one_step`.
- **1-2 '처음 설정' 체크리스트**: 전 — 제목 "마지막 단계: 블록체인 연결(RPC)" 카드와 `나중에`, 카드 밖 확장 링크, RPC가 있으면 `지갑 열기`만. 후 — 카드 "처음 설정" 하나에 ① 블록체인 연결(RPC)(1-1의 칸, 주소가 이미 있으면 "RPC 주소 n개 · 이번 실행 테스트: 작동 a · 실패 b"와 `RPC 설정 열기`), ② dApp 연결(선택, 둘 중 하나: Chrome 확장 상태 + `설치 방법`(S23, `← 돌아가기`가 S08로) / WalletConnect "Project ID 없음·설정됨" + `설정`(S13)), ③ 첫 입금 시험("실제 자산은 소액으로 받기 → 보내기를 한 번 해 보세요. EVM 탭은 Sepolia 테스트넷으로 시작합니다." + `받기`). `지갑 열기`는 RPC가 없어도 늘 맨 아래. S08에서 연 설정 → 네트워크(RPC)와 S13은 맨 위 링크가 `← 처음 설정으로`(`App::back_row`, 새 플래그 `done_return`)이고 S08로 돌아온다. S08 플래그(`done_imported`·`done_start`·`done_yubikey`·`done_return`·연결 결과)는 `지갑 열기`·`← 메인으로`·잠금에서만 지운다. 가져오기·개인키로 시작 뒤에는 정보 카드 "잔액이 안 보이면": Sepolia로 시작한다는 줄 + `Ethereum 메인넷으로 보기`(네트워크 칩과 같은 `evmChainId` 저장), 계정을 자동으로 찾지 않으니 "내 계정 → 계정 추가"·Solana "다른 경로 스캔"(가져오기만), Bitcoin·Zcash가 꺼져 있으면 그 줄(꺼진 것만).
- **1-3 RPC 공급자 카드**: 전 — `저장`(주) · `네트워크 URL 생성` · `자격 정보 삭제`(늘 켜짐, 확인 없음), 생성은 늘 덮어쓰기 오버레이, 빈 칸이면 E-KEY-004. 후 — 주 `저장하고 RPC 주소 만들기`, 보조 `자격 정보만 저장`(저장 뒤 이 템플릿 대상에 주소가 없으면 "RPC 주소는 아직 없습니다 — “저장하고 RPC 주소 만들기”를 누르세요."), 위험 `자격 정보 삭제`(저장된 것이 있을 때만, 1-6 확인). 덮어쓰기 오버레이는 대상 중 이미 주소가 있는 네트워크가 있을 때만(덮어쓰기 기본 끔 그대로), 없으면 바로 만든다. 칸이 비어 있고 저장된 것도 없으면 E-KEY-004 대신 "위 칸에 엔드포인트 이름과 토큰(또는 주소 전체)을 넣으세요." 생성 안내 "RPC 주소 n개를 만들었습니다. 연결을 확인하는 중입니다 — 결과는 아래 각 행에 나옵니다."(건너뛴 네트워크가 있을 때만 "템플릿 항목이 없는 m개는 직접 입력하세요: …"). QuickNode 도움말에 쓸 체인을 엔드포인트에 하나씩 켜야 한다는 줄, rpc.json이 있으면 카드 첫 줄 안내.
- **1-4 테스트 큐·요약·3상태**: 전 — `테스트`는 네트워크마다 직접, 생성·교체·가져오기 뒤 결과 없음, "테스트 중…"이 빨간 오류 띠. 후 — `App::rpc_tests`(`VecDeque<NetworkId>`, 중복 없음): `RpcEvent::Test` 답이 올 때마다 다음 `RpcJob::Test` 하나만 보낸다(FIFO 작업자가 잔액·보내기 작업을 오래 막지 않게). "네트워크별 RPC 주소" 머리에 "RPC 주소 11/13개 설정 · 이번 실행 테스트: 작동 9 · 실패 1 · 안 함 1", 실패한 네트워크 이름 링크(새 ID 범위 16,720–16,783), `모두 테스트`(도는 동안 꺼진 `테스트 중 3/11`). 자동 테스트: `generate`·`save_replacement`·`finish_rpc_import`가 쓴 네트워크(가져오기 안내도 "연결을 확인하는 중입니다 — 결과는 아래 각 행에 나옵니다."). `rpc_messages`는 3상태(`TestState`: 테스트 중 = 정보, 작동 = 완료, 실패 = 오류 색), 설정 → Bitcoin `Esplora URL` 테스트도 같다. 요청 내용(eth_chainId·getGenesisHash·getblockchaininfo·getblockhash 0, 주소 없음)과 로그는 그대로, EVM 테스트 범위도 넓히지 않았다.
- **1-5 그 네트워크 행으로 바로**: `App::open_rpc_row(network, edit)` — 설정 → 네트워크(RPC)를 열고 그 행의 컨트롤을 보기 안으로 스크롤(`app_scroll::reveal_control`을 `pub(crate)`로), `edit`면 `replace_target`으로 입력 칸(`ES_PASSWORD` 그대로)을 열고 포커스, 아니면 그 행의 `테스트`에 포커스. EVM·Solana·Bitcoin(게이트)·Zcash 탭의 `RPC 설정하기`는 탭별 새 ID로 그 탭의 지금 네트워크를 `edit`로 연다. 설정 탭 `네트워크(RPC)`·`네트워크(RPC) 설정으로`·S08 `RPC 설정 열기`는 그대로 맨 위. 템플릿 자격 정보가 저장되어 있고 그 네트워크에 템플릿 항목이 있으면 열린 칸 위에 "{QuickNode|알케미} 자격 정보가 저장되어 있습니다 — 위 “저장하고 RPC 주소 만들기”로 비어 있는 주소를 한 번에 만들 수 있습니다." S08 ✗ 줄과 요약의 실패 이름은 `edit` 없이 연다.
- **1-6 지우기 확인**: 네트워크 행 `삭제` → `Confirm::RpcUrlDelete(NetworkId)`("RPC 주소 지우기": "{이름} ({NetworkId})의 RPC 주소를 지웁니다. 저장된 주소는 다시 볼 수 없어, 다시 쓰려면 “저장하고 RPC 주소 만들기”({공급자} 자격 정보: 설정됨/없음) 또는 “입력”으로 다시 넣어야 합니다. 이 네트워크에 확정 전 거래가 있으면 주소를 다시 넣을 때까지 상태 확인이 멈춥니다."), `자격 정보 삭제` → `Confirm::TemplateDelete`(끝 "…이미 만든 네트워크별 RPC 주소는 그대로이고, 새 체인 주소를 만들 때 다시 넣어야 합니다."), AI 설명 `키 삭제` → `Confirm::LlmKeyDelete`(끝 "…AI 설명을 다시 쓰려면 키를 다시 넣어야 합니다."). 버튼 `지우기`(위험)·`취소`. 지운 뒤 그 행이나 카드에 완료 띠. 지우는 함수·저장·E-APP-002 처리는 그대로이고 확인만 더했다.
- **1-7 §7 문구와 용어**: E-KEY-005 "RPC 주소가 없습니다. 설정 → 네트워크(RPC) → “네트워크별 RPC 주소”에서 입력하거나 “저장하고 RPC 주소 만들기”로 만드세요.", E-KEY-004 "선택한 RPC 공급자의 자격 정보가 저장되어 있지 않습니다. 설정 → 네트워크(RPC) → “RPC 공급자”에서 먼저 저장하세요.", E-KEY-001(다른 PC·다른 Windows 사용자에서 옮겨 온 경우 정상, 다시 넣을 곳), E-RPC-004(대시보드의 초당 한도·크레딧), E-TX-002(활동에서 상태, EVM `수수료 올리기`·`취소`), E-TX-005(확정·폐기되면 공간이 생김; spec/02 §5.4·§10.2), E-VLT-007(다른 프로그램을 닫거나 다시 시작), E-TX-003·E-VLT-005(다시 시작, 반복되면 yw-app.log의 코드 줄), E-BTC-004(인덱서 종류 확인), E-APP-005(잠시 뒤, 계속되면 그 사이트 연결 해제). ### 3. 남긴 것과 이유·대안

- **D1 메인 탭의 RPC 실패 띠에서 그 행으로**(1-5의 나머지): 배치 2가 같은 `open_rpc_row`와 3상태를 메인 화면 띠에서 쓴다(이 배치는 함수와 설정 화면까지).
- **D2 S08 `받기`에서 돌아오기**: ③의 `받기`(S12)는 지금처럼 `← 메인으로`라 S08로 돌아오지 않는다. `← 처음 설정으로`는 설정 → 네트워크(RPC)와 S13에만 그렸다(배치 범위). 받기 화면의 뒤로 링크를 바꾸면 S04(백업 확인 전)의 `받기`와 갈래가 늘어 다음 배치에서 함께 본다.
- **D3 W08 시간 안내 문구의 화면 이름**: 제안 문구는 "(S04에서 다시 볼 수 있습니다)"였지만 S04는 사용자에게 보이지 않는 화면 코드라 그 화면의 버튼 이름으로 "(닫혀도 “복구 단어 보고 백업 확인”으로 다시 볼 수 있습니다)"를 썼다.
- **D4 직접 친 주소의 `테스트`**: `교체` 칸에 친(저장 전) 주소의 `테스트`는 큐를 거치지 않고 바로 보낸다(비밀인 주소를 큐에 들고 있지 않기 위해). 그래서 그 순간에는 큐의 테스트와 둘이 함께 돌 수 있다(많아야 하나 더).
- **D5 네 탭 상태 줄 형식 통일**: 용어만 "RPC 주소 없음"으로 맞추고 줄 형식(괄호·구분자·인덱서 표시)은 그대로 두었다(제안 범위 밖, 배치 2의 메인 띠와 함께).
- **D6 §7의 다른 "엔드포인트" 문구**(E-RPC-003·E-RPC-009·E-RPC-010): 공급자 대시보드 용어와 맞닿아 있어 이번에는 바꾸지 않았다. E-KEY-001은 문장을 고치면서 "RPC 주소·API 키"로 맞췄다.
- **D7 수동 확인 기록(docs/acceptance)**: 옛 날짜의 기록 문서는 당시 문구 그대로 두었다. 다음 수동 확인 때 새 문구(S08 `연결하기`, `저장하고 RPC 주소 만들기`)로 적는다.
