# UI/UX 검토 — 2026-10-31

대상: main fe22172(개인키 가져오기·키 전용 지갑, Bitcoin 주소 형식, Solana·Bitcoin dApp 메시지 서명, EVM·SOL·BTC 호환 모드, 확인 1 = 확정, `지금 다시 전송`, 보안 띠가 모두 들어간 상태)의 주 창·승인 창·확장 팝업. 기준 사용자는 "지갑을 혼자 쓰는, 전문가는 아닌 주인 한 명"이다.
방법: 화면 투어(`scripts/screenshot-tour.ps1`, 버리는 임시 데이터 폴더)로 고치기 전 화면을 찍어 보고, spec/04·05·08과 UI 코드(`crates/yw-app/src/ui/*`, `app*.rs`, `extension/popup`, `extension/src/popup*.js`)를 대조했다. 투어가 찍지 않던 창(사이트 연결 창, Solana 메시지 서명 창, Solana·Bitcoin 연결이 있는 연결된 사이트)은 투어에 장면을 더해 확인했다. 이전 검토는 [ux-review-20261028.md](ux-review-20261028.md).

## 2. 고친 것 (전 → 후)

- **F1 보이지 않는 버튼**: `다른 계정으로 바꾸기 (메인)`(새 id `SWITCH_ACCOUNT` 201)과 `네트워크(RPC) 설정으로`(새 id `GO_NETWORK` 205)에 고유 id를 주고 동작은 같게 했다. 시험 `every_screen_has_unique_control_ids`가 세 체인 탭 × 주요 화면 24개(메인, 보내기·결과·받기 세 체인, 주소록, 토큰·체인 추가, 연결된 사이트, 설정 7구역, 완료)에서 id가 겹치지 않음을 확인한다. 11번: 빈칸 → 링크가 보인다.
- **F2 Bitcoin 탭 순서**: 네트워크 카드 → 선택 계정 카드(이름·노드·큰 사용 가능 잔액·`보내기`·`받기`) → "Bitcoin 계정" → UTXO → 활동. 키 전용 지갑에 Bitcoin 키가 아직 없으면 지금처럼 계정 카드만. 16번: 보내기·받기가 첫 화면에 보인다.
- **F3 확장 팝업**: 계열마다 실제 확장을 끄라는 경고는 그 계열의 모드가 `off`가 아닐 때만 보이고(라디오를 바꾸면 즉시), 저장 결과 줄은 그 카드 안(`mode-saved`·`sol-saved`·`btc-saved`)에 나온다. Solana·Bitcoin 공통 안내("연결과 메시지 서명만")는 두 카드 앞의 한 줄로 옮겼다. EVM 카드 제목은 앱 탭과 같은 "EVM (이더리움 등) dApp에 보이는 지갑". 미리보기(`scripts/popup-preview.html`)는 `popup.html`의 `<body>`와 같게 맞추고 새 시험 `scripts/popup-preview.test.mjs`가 둘이 다르면 실패한다. 투어는 팝업 전체가 보이도록 340×1160으로 찍는다(실제 Chrome 팝업은 600px 높이에서 스크롤). 19번: 빈 카드 두 개 → 세 계열 모두 보이고 경고는 켠 계열(MetaMask) 하나.
- **F4 메시지 서명 창**: Solana·Bitcoin 메시지 서명에는 "자산 변화" 카드가 없다(EVM 메시지 서명과 같은 규칙). 접힌 상세 링크는 모든 종류에 맞는 "자세히 ▸ (나머지 항목·원본 데이터)". 표시 모델·digest는 그대로이고 그리는 쪽(`approval_view`)만 바뀌었다. 27번.
- **F5 띠 한 겹**: Bitcoin testnet4는 전용 주황 배너만 그린다(메인·보내기·받기·결과·수수료 올리기). 메인넷 배너와 EVM·Solana 테스트넷 띠는 그대로.
- **F6 가져오기 접기**: 계정 카드에는 한 줄 "다른 지갑에서 쓰던 Bitcoin 개인키(WIF)도 이 목록에 더할 수 있습니다. 누르면 주소 형식을 고릅니다." + `개인키 가져오기`. 누르면 `계정 추가`처럼 같은 자리에 설명·형식 라디오·`다음 (개인키 입력)`·`취소`가 열린다. 클릭이 한 번 늘지만 드문 작업이고, 매일 보는 카드가 짧아진다. 키 전용 지갑의 빈 Bitcoin 카드(가져오기가 유일한 행동)는 처음부터 라디오를 보인다.
- **F7 주소 형식 이름**: 쉬운 이름 → 접두 → 기술 이름 순서 `네이티브 세그윗 (bc1q…, P2WPKH)`·`탭루트 (bc1p…, P2TR)`·`호환 세그윗 (3…, P2SH-P2WPKH)`·`레거시 (1…, P2PKH)`(S18 라디오, Bitcoin 탭 가져오기, S19 "주소 형식" 줄). 승인 창의 Bitcoin 표시(digest 안)는 바꾸지 않았다.
- **F8 연결된 사이트**: 카드 제목 `https://app.example.org  ·  Solana`처럼 origin 전체 뒤에 계열, 맨 위에 `연결 EVM 2곳 · Solana 1곳 · Bitcoin 1곳`, Solana 연결에 계정 라벨, 설명을 "아래 계정의 주소를 볼 수 있고, EVM 사이트는 잔액과 거래 기록도 읽을 수 있습니다…"로. 18·29번.
- **F9 단축키**: Ctrl+1/2/3 = EVM·Solana·Bitcoin 탭(주 창이 앞에 있고 S10이며 비밀 창이 없을 때만, 탭을 누른 것과 같은 경로). 설정 → 브라우저·진단·정보 → "정보" 카드에 "단축키" 줄(Ctrl+L 잠금 · Ctrl+1/2/3 체인 탭 · Tab 다음 칸).
- **F10 용어**: "같은 니모닉에서" → "같은 복구 단어에서".
- **투어 장면 추가**: 26 사이트 연결 창(EVM), 27 Solana 메시지 서명 창, 29 연결된 사이트의 Solana·Bitcoin 카드.

## 3. 점검 항목별 결과

- **첫 실행**: 세 갈래가 분명하다. "개인키만 있습니다" 카드가 복구 단어가 없다는 점을 본문에 말한다. 바꾸지 않음.
- **RPC 설정 수고**: 완료 화면(06)이 왜 필요한지와 `RPC 설정하기`를 주고, 설정은 QuickNode 이름·토큰 두 칸(주소 전체 붙여넣기 가능) → `네트워크 URL 생성` 한 번으로 모든 네트워크가 채워진다(17). 공급자 계정을 만드는 일 자체는 앱 밖이라 줄일 수 없다.
- **이동·클릭 수**: 받기 1번(메인 → `받기`), 보내기 3번(보내기 → 입력 → `검토` → 승인 창), 활동은 메인 아래, 연결 1번 + 승인. Bitcoin은 F2 전까지 스크롤이 더 필요했다. 탭 전환은 이제 키보드로도 된다.
- **정보 밀도·위계**: 큰 잔액·주 버튼 2개·보조 버튼 구분은 잘 지켜진다. 계정이 하나일 때의 중복(D3)과 Bitcoin 탭의 가져오기 구역(F6)이 밀도를 높였다.
- **용어**: "복구 단어(니모닉)" 첫 언급 규칙, "가져온 키" 배지, "확정"이 일관된다. 남은 "니모닉"은 오류 문구(§7, 코드 고정)와 로그·AI 고지(무엇을 보내지 않는지 나열) 뿐이다. 주소 형식 이름은 F7로 통일.
- **오류의 다음 단계**: 엔드포인트 없음은 `설정에서 URL 입력`, Bitcoin 꺼짐은 `Bitcoin 설정`, 차단 체인은 `설정에서 다시 고정`으로 이어진다. §7 문구 자체에 다음 단계를 붙이는 작업은 10-28 검토에서처럼 별도 변경으로 남는다.
- **빈 상태**: 활동·토큰·사이트·주소록·키 전용 지갑의 빈 탭 모두 다음 행동을 말한다.
- **경고 피로**: F3(팝업 세 띠), F5(Bitcoin 두 겹)를 줄였다. D2는 위험 판단 코드라 남겼다. 메인넷 빨간 띠와 테스트넷 띠는 체인마다 하나라 그대로 둔다.
- **승인 창 가독성**: 출처(헤더 첫 줄) · 무엇을(요약 한 문장) · 위험(띠·태그)이 한눈에 들어온다. 메시지 서명의 혼란(F4)을 없앴다. 출처 문구(D1)만 남았다.
- **확장 팝업**: F3. 호환 모드가 무엇인지는 모드 카드 설명 한 줄로 충분하고, 실제 지갑 경고는 이제 켤 때 나타나 의미가 분명해졌다.
- **연결된 사이트 (세 체인)**: F8. 계열별 해제는 카드의 `연결 해제`, 전체는 맨 아래 `모든 사이트 연결 해제`(확인 창 유지).
- **설정 구성**: 구역 탭 7개(보안·네트워크(RPC)·EVM 체인·Solana·Bitcoin·AI 설명·브라우저·진단·정보)와 카드별 도움말은 10-28 그대로 충분하다. F1의 Bitcoin 구역 버튼이 다시 보인다.
- **키보드·포커스**: Tab 이동(`IsDialogMessageW`)과 포커스 링, 승인 창의 Tab·Enter·Space·Esc·PgUp/PgDn은 있다. F9로 탭 단축키를 더했다.
- **DPI**: 모든 크기는 DIP이고 투어는 100%(96 DPI)에서 찍었다. 125–200%는 여전히 수동 확인 항목이다(잘림·겹침은 100%에서 보이지 않았다).
- **잘림**: 주소·해시는 줄이지 않고 줄바꿈한다. 팝업 Bitcoin 설명 `sats-connect(Xverse)`도 줄바꿈된다.
- **버튼 일관성**: 화면마다 주 버튼 하나(체인 탭은 `보내기`·`받기`), 위험 버튼은 삭제·연결 해제·폐기. F6의 `다음 (개인키 입력)`은 열린 선택지의 주 버튼이다.
- **다크/라이트**: 라이트 전용(spec/04 §1.6, 팝업도 같은 토큰). 바꾸지 않음.

## 4. 남긴 것과 이유·대안

- **D1 요청 출처 — 해결(같은 날, 뒤의 커밋)**: 세 체인 모두 `Your Wallet 앱`(`yw_core::approval::APP_ORIGIN_TEXT`)으로 맞췄다. 표시 텍스트라 display 바이트·digest에 들어가며(digest의 `origin_serialized`는 그대로 `yw-app`), 앱 출처 V14 골든 두 벌을 기록 절차대로 다시 고정했다(독립 재계산 통과, 사이트 출처 골든은 그대로). 12·13·21을 다시 찍었다. 아래는 당시 기록.
- **D1 요청 출처 `Your Wallet 앱 (yw-app)`**(당시): 이 문구는 yw-core 표시 모델(`evm/display` 헤더, `sol/display`)에서 만들어 **approval digest에 묶이고**, `crates/yw-app/tests/approval_golden.rs`가 표시 바이트·digest를 고정한다. 문구 하나 때문에 골든을 다시 고정하는 것은 보안 검토가 함께 봐야 할 변경이다. 제안: Bitcoin과 같은 `Your Wallet (이 앱)`으로 세 체인을 맞추고, 같은 커밋에서 V14 골든을 기록 절차(`print_v14_goldens`, 독립 재계산 확인)대로 다시 고정한다.
- **D2 단순 송금의 "보내는 자산만 있고 받는 자산이 없습니다"**: 시뮬레이션 해석(yw-core `evm::simulate` 경고)이 정하는 위험 경고라 이번 범위(보안 동작 약화 금지) 밖이다. 제안: calldata가 없는 네이티브 전송이고 자산 변화가 "보냄 {금액}" 한 줄과 정확히 같으면 이 경고를 `정보` 등급으로 내리거나 요약 문장에 합친다(토큰 승인·스왑처럼 받는 것이 기대되는 호출에는 지금처럼 `주의`).
- **D3 계정 하나일 때의 중복**: "내 계정" 카드는 계정 추가·이름 바꾸기·가져오기의 자리이기도 해서 숨기면 기능을 찾기 어려워진다. 제안: 계정이 하나면 그 카드에서 주소·잔액 줄을 빼고 이름과 버튼만 남긴다(선택 계정 카드가 이미 보임). 화면 시험 여러 개가 행 구성을 고정하므로 별도 변경으로.
- **D4 Bitcoin 메시지 서명 창 장면**: 투어에서 Solana 메시지 창을 거부한 직후 같은 origin의 `btc_signMessage`를 넣으면 창이 열리지 않았다(초안 생성·grant·preflight 조건은 모두 통과함을 확인). 투어 하네스가 창을 닫는 방식(`finish_approval` 직접 호출) 때문인지, 실제 큐의 동작인지는 확인하지 못했다. 실제 앱에서 "Solana 메시지 거부 → 바로 Bitcoin 메시지 요청"을 수동으로 확인할 항목으로 남긴다.
  - **해결(같은 날)**: 큐도 투어 하네스도 아니었다. 승인 창 라벨 표에 표시 키 0x0405(SIWS 필드)·0x0406(서명 방식)이 없어, 모든 Bitcoin 메시지 서명 창과 SIWS·오프체인 Solana 창이 `validate_for_display`에서 E-UI-001로 바로 닫혔다(순서와 무관). 라벨을 넣고, 코어가 받는 모든 표시 키에 라벨이 있는지와 같은 사이트의 SOL·BTC·EVM 요청이 거부 뒤에도 차례로 창을 얻는지를 회귀 시험(`app_chain_sites::tests::chain_message_windows_follow_each_other_after_a_rejection`)으로 고정했다. 투어에 SIWS 창(28)과 Solana 창 거부 직후의 Bitcoin 메시지 창(30)을 더했다.
- **승인 무장 지연(1초)**: 그대로 둔다. 회색 `승인`이 왜 회색인지 모를 수 있으니, 대안으로 무장 전 상태 줄에 "잠시 뒤 승인할 수 있습니다"를 보이는 것을 제안한다(무장 시간·계산은 그대로).
- **§7 오류 문구의 다음 단계, 125–200% DPI 시각 확인, 버튼 hover 표시**: 10-28 검토에서 남긴 그대로.
- **팝업 길이**: 세 계열 카드가 모두 보이면 600px 팝업에서 스크롤이 필요하다. 대안: `off`인 Solana·Bitcoin 카드를 한 줄 요약으로 접기. 이번에는 경고를 줄여 길이를 먼저 줄였다.
