# UI/UX 검토 — 2026-11-08

대상: main 77a4707(보안 수정 병합 뒤) — 11-07 검토 뒤에 들어온 기능(복구 단어 여러 개 D37, YubiKey 연결(복구 단어 없이)·PIN 상태 초기화, 추가 복구 단어의 Solana·Bitcoin·Zcash 계정, 설정 보안 스냅샷 등)이 모두 있는 상태. 기준 사용자는 지난 검토와 같이 "지갑을 혼자 쓰는, 전문가는 아닌 주인 한 명"이고, 이번에는 다섯 사람의 눈으로 나눠 봤다: (1) 처음 쓰는 주인(설치 → 첫 실행 → 백업 확인 → RPC → 확장 → 첫 입금), (2) 매일 쓰는 주인(여러 체인·계정·토큰, 받기·보내기), (3) dApp 사용자(확장 팝업, 연결 창, 승인 창, WalletConnect), (4) 보안을 중시하는 YubiKey 사용자(복구 단어 없는 지갑, 카드 1–2장, PIN, 초기화), (5) 파워·유지보수 사용자(설정 구성, RPC, 변조 띠, 키보드, DPI). 이전 검토: [11-07](ux-review-20261107.md), [10-31](ux-review-20261031.md), [10-28](ux-review-20261028.md).

방법: 다섯 검토가 화면 투어(`ui::tour::screenshot_tour`, 버리는 임시 데이터 폴더)와 UI 코드(`crates/yw-app/src/ui/*`, `app*.rs`)·spec/04·이전 검토를 대조해 낸 제안 47건을 하나로 합쳐(겹치는 제안: 창 크기 기억 2건, 설정 탭 넘침 2건, `RPC 설정하기` 문구 3건, 복구 단어 라벨 2건 등) 영향 순으로 정리했다. 영향 높음 + 작거나 중간 노력인 것부터 고쳤고, 보안 관련 항목은 보안 동작(승인 무장 지연, 2초 누르기, 캡처 제외, 복사 규칙, 위험 등급·차단, PIN 규칙, 확인 창)을 그대로 둘 때만 고쳤다. 고친 화면만 투어를 다시 찍었다.

원칙(바꾸지 않음): 승인 무장 지연(창이 앞에 나온 뒤 1초, 모든 누름 계산), 고위험 체크 1개 + 2초 누르기, 비밀 창 캡처 제외, 복사 규칙, 위험 등급과 차단, digest에 묶인 표시, PIN 규칙(작업 사이 캐시 없음, 공장 PIN 미전송), 파괴적 동작의 확인 창, 주소를 줄이지 않는 규칙, §7 오류 문구. 이번 변경은 위험 표시를 **더하기만** 했다(메인넷 띠, 백업 전 띠, 확인 창 2개).

## 2. 고친 것 (전 → 후)

- **U1 백업 확인 다시 묻기**(보안 관련 — 강화): vault가 틀린 답의 위치를 그 복구 단어에 대해 성공·잠금(다시 잠금 해제)까지 기억하고(`Vault::retry`), 다음 challenge가 **새 id로 같은 위치 4개**를 묻는다. 새 YubiKey 지갑의 메모리 속 단어(`PendingEnrol::retry`)도 같다. 결과는 여전히 네 단어 전체의 일치/불일치뿐이라 위치별 맞음/틀림을 알 수 없고(단어별 오라클 없음), 횟수 제한 없음도 그대로다. T-BACKUP-FAIL: "입력한 단어가 맞지 않습니다. 새 위치로 다시 확인합니다." → "입력한 단어 중 종이와 다른 것이 있습니다. 같은 위치(3·9·16·22번째)를 다시 묻습니다." + 단어를 다시 볼 수 있는 흐름이면 "이 창을 닫고 복구 단어를 다시 보면서 이 네 단어를 종이와 대조해 고치세요", 새 YubiKey 지갑이면(창을 닫으면 단어가 지워짐) "종이의 이 네 단어를 다시 확인하세요…처음부터 다시 만드세요". 시험: `vault::tests::backup_confirmation`에 "틀린 뒤 같은 위치" 단언. spec/02 §8.3, spec/04 §2.3·T-BACKUP-FAIL·UI-M3-07, spec/09 M3-4, spec/10.

## 3. 남긴 것과 이유·대안

- **D1 첫 실행에서 QuickNode 주소 한 번 붙여넣기로 RPC 연결·자동 테스트**(높음/중간): 자격 정보 저장 → 없는 주소만 생성 → 주요 네트워크 자동 테스트까지 한 화면에서 하는 새 흐름이라 RPC 작업자·`begin_generate` 경로를 함께 바꿔야 한다. 이번에는 RPC 없음 문구와 버튼(U17)만 고쳤다. 대안: S08 카드 안 ES_PASSWORD 칸 하나 + `연결하기`(기존 `quicknode_input` → GENERATE(덮어쓰기 없음) → 각 `RpcJob::Test`) — 다음 변경으로 제안.
- **D2 받기 화면 네트워크 칩·첫 시작 네트워크 묻기**(중간): 받기 화면에서 `evmChainId`를 바꾸면 메인의 선택과 승인 창 체인까지 함께 바뀌므로 칩 동작을 메인과 맞춰 따로 검토해야 한다. 이번에는 받기 제목에 네트워크·배지를 넣고(U10) 같은 주소 안내를 QR 위로 올렸다.
- **D3 메인 "처음 할 일" 카드, 모든 EVM 체인 잔액 줄, 계정 바꾸기 접이식 목록, 카드 요약·접기(갱신 시각·Zcash 키 출처·HyperCore 한 줄)**(중간): 메인 첫 화면 배치를 크게 바꾸는 묶음이라 한꺼번에 설계하는 편이 낫다. HyperCore 접기는 11-07 D3 그대로 남김.
- **D4 Bitcoin 보내기 폼의 수수료 미리 보기**(높음/중간): 폼을 열 때 `estimatesmartfee`·`getmempoolinfo`를 읽는 새 RPC 작업과 검토 전 계획(승인 요청 없음)이 필요하다. Solana만 SOL 표기로 고쳤다(U21).
- **D5 W11 PIN 창의 카드 연결 상태·터치 진행·틀린 PIN 같은 창 오류**(높음/중간, 보안 관련): 키 작업자의 입력별 진행 이벤트와 창 수명(제출 뒤에도 열어 둠)을 바꾸는 변경이라 PIN 버퍼 이동·120초 기한·캡처 제외를 함께 다시 확인해야 한다. 공장 PIN 상태의 앞당긴 안내(U7의 YubiKey 쪽)도 같은 이유로 남겼다 — 지금은 카드 단계의 T_CARD_FACTORY_PIN과 `PIN 설정` 띠.
- **D6 이미 등록한 카드에 Solana 슬롯 추가, 잠긴 PIN 풀기(RESET RETRY COUNTER), 등록 마법사 조합 라디오·관리 키 자동, 카드 별명**(높음–중간, 보안 관련·큰 노력): 카드에 쓰는 새 APDU 흐름이라 에뮬레이터 시험과 함께 별도 변경으로. 대안 문구: 잠김 오류가 가리키는 기능이 없으니 다음 변경 전까지는 "YubiKey 비우기 → 애플릿 초기화(키 삭제)"가 유일한 앱 안 경로임을 확인 문구가 이미 말한다.
- **D7 사이트 기본 계정 바꾸기·계정 빼기(S13)**(U9의 (b)): `accountsChanged` 순서 보내기와 뺀 계정의 대기 서명 4100 처리를 함께 바꾸는 변경이라 남겼다. 이번에는 연결 창의 기본 선택과 안내(U9 a)만.

- **D9 RPC 용어 통일(E-KEY-005 문구 변경)·상태 줄 형식, RPC 오류 한 줄 + 그 네트워크 줄로 스크롤, 네트워크별 RPC 목록 요약·`모두 테스트`, 진단 카드, 수수료 상한 현황·E-TX-001 이동**: §7 문구는 코드와 함께 고정(11-07 D6)이고 나머지는 설정 화면 배치 변경이라 남겼다. 링크 이름은 `RPC 설정하기`로 통일했다(U17).
